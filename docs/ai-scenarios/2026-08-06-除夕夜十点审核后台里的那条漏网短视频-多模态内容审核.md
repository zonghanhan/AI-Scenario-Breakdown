# 2. 业务场景故事

## 《除夕夜十点，审核后台里的那条漏网短视频》

### 第一章：零点前一小时，上传队列开始发烫

腊月二十九晚上 22:07，「年味」社区 App 的春节活动进入冲刺阶段。运营拉了「晒年夜饭短视频领红包」话题，预估当晚会有平时 8 倍的 UGC 上传量。

内容安全负责人林薇盯着三块大屏：

- 待审队列：18,432 条（还在涨）
- 机审通过率：91.3%
- 人审平均等待：47 秒

刚转行做 AI 产品的陈默信心满满。过去两个月，他和算法、工程搭了一套「多模态内容审核系统」：用户发布图文或短视频后，先走机器预审，高风险进人工，低风险直接放行，中等风险抽样复核。

活动规则写得很清楚：禁止涉政、色情低俗、虚假医疗、侵权搬运、诱导站外交易。听起来都是标准红线，但林薇在群里只问了一句：「去年除夕，一条『养生偏方』视频在机审里待了 11 秒就上线了，第二天被监管部门点名。今年你的系统，敢不敢跟我赌一条漏网？」

陈默心想：我们有图像识别、OCR 抽字幕、音频转文字、文本分类四套模型并联，还有规则引擎兜底，应该稳。

22:19，一条 42 秒的竖屏视频进入队列。封面是一锅热气腾腾的红烧肉，标题写着「奶奶秘方，三高人群也能放心吃」。机审 8 秒后给出结论：**低风险，建议放行**。

22:21，视频出现在话题流第三位，点赞开始往上窜。

22:34，林薇的电话打过来：「这条已经在处理了，用户举报说你在卖『降糖神药』。你告诉我，机审 8 秒放行，审了个啥？」

**悬念**：陈默意识到，问题不是「有没有审核」，而是「多模态内容里，机器到底看到了什么、没看到什么」。

---

### 第二章：一条短视频进来，系统其实在并行读四个「频道」

陈默拉着算法和工程同学复盘这条漏网视频。用户上传的并不只是「一锅红烧肉」——完整素材包含：

- **画面**：厨房场景、食材特写、老人出镜、瓶瓶罐罐的特写（无清晰品牌，但标签类似药品包装）
- **字幕**：底部硬字幕「配合本产品，三天见效」
- **口播**：老人说「我血糖从 12 降到 6，就靠这个」
- **标题 + 描述**：「三高福音」「私信领取试用」

系统实际走的流程，比「扫一眼有没有黄图」复杂得多：

**第一路：视觉审核（CV 模型 + 规则）**

图像模型对每一帧（或关键帧采样）打标签：食品、人物、文字区域、疑似药品包装、二维码、裸露皮肤面积等。

这条视频的画面风险分不高——没有明显色情暴力，食品场景命中了「正常」类目。但「药瓶类物体」在某一帧置信度只有 0.41，低于拦截阈值 0.65，被记为「弱信号」，没有单独触发拦截。

**第二路：OCR + 文本审核（把画面里的字「抠」出来）**

系统对视频帧做 OCR（光学字符识别，从图片里把文字提取出来），拼成一条「画面文字流」：「配合本产品，三天见效」。

文本审核模型把「三天见效」命中为「夸大疗效」高危词，但这条 OCR 结果和另一路字幕识别结果在合并环节出了岔子——硬字幕被 OCR 识别成「配合本产晶」（错字），关键词规则没命中，模型分数被稀释到中等。

**第三路：语音转文字 + 文本审核（ASR 链路）**

音频转写（ASR，自动语音识别）把口播转成文字：「我血糖从 12 降到 6，就靠这个」。

医疗功效宣称命中了「疾病治疗暗示」类目，风险分 0.78。但系统配置里，**单模态高分不直接封禁**，需要「至少两路模态同时高危」才自动拦截——因为去年误杀太多「用户吐槽吃药」的正常视频，运营要求降低了单路拦截的激进程度。

此时：语音高危 + 画面弱信号 + OCR 文本因错字未高危 = **综合分 0.62，落在『低风险放行区』**。

**第四路：标题描述 + 账号画像（结构化文本）**

标题「三高福音」、描述「私信领取试用」在文本审核里命中「导流 + 医疗暗示」组合，风险分 0.71。但发布接口为了提升春节活动体验，对「标题描述」和「视频本体」做了**异步审核**——视频先上线，标题违规可以后补拦截。

陈默看着时序图，倒吸一口气：不是模型完全没看到问题，是**·多路信号没有在同一时间窗口内汇合决策**，再叠加异步策略，给了漏网窗口。

### 第三章：人审不是「擦屁股」，而是系统里的正式车道

漏网视频上线 15 分钟后，用户举报进入「高优人审池」。值班审核员小周打开后台，界面不是简单的一个播放按钮，而是**多模态证据面板**：

| 面板区块 | 内容 | 系统预标注 |
|---------|------|-----------|
| 时间轴风险热力图 | 第 8–12 秒药瓶特写、第 28 秒口播峰值 | 画面弱信号、语音高危 |
| 转写稿 | 带时间戳的 ASR 全文，高危句高亮 | 「血糖从 12 降到 6」 |
| OCR 字幕轨 | 帧级文字 + 置信度 | 「三天见效」低置信 OCR |
| 相似内容召回 | 3 条历史违规样本 | 同话术不同账号矩阵 |
| 账号风险 | 注册 3 天、粉丝 12、历史 1 次导流 | 新号高危 |

小周 40 秒结案：「虚假医疗宣传 + 站外导流」，处置选「下架 + 限流账号 + 阻断私信关键词」。

林薇问陈默：「如果没有人举报，这条要挂多久？」

陈默答不上来。因为当前系统的「离线回扫」只对机审高分内容做二次模型升级检测，对**已放行的低风险内容**没有周期性重审；而春节活动期间，为了省算力，回扫采样率从 5% 降到了 1%。

这一轮复盘让团队达成了一个产品共识：**人审不是机审失败后的耻辱，而是分级审核架构里的正式车道**——关键不是消灭人审，而是让人审只看「机器不确定且后果严重」的内容。

### 第四章：红线不是一条，是分层闸门

接下来三天，陈默重新画了一张「多模态审核闸门图」，把内容从上传到可见拆成五道关卡：

**闸门 0：发布前客户端预检（端侧 + 轻量规则）**

- 拦截裸露封面、超大文件、明显违禁文件名
- 不做重模型推理，只做体验和带宽保护
- 误杀成本低，宁可提示「请更换素材」

**闸门 1：同步机审（必须在响应 SLA 内出结果）**

目标：300 ms–3 s 内给出「放行 / 拦截 / 送人审」三态。

- 文本标题描述：必须同步审完，导流和绝对违禁词不允许异步
- 视频本体：可走「先发后审」仅当业务明确接受风险且账号等级低危；本次春节活动的错误就出在把「标题」也放进了异步

**闸门 2：多模态融合决策（不是四路各判各的）**

产品规则从「两路同时高危才拦」改成**分场景融合**：

| 场景类型 | 融合策略 | 理由 |
|---------|---------|------|
| 绝对违禁（涉政、儿童色情） | 任一路命中即拦 | 零容忍，接受一定误杀 |
| 医疗宣称、金融收益 | 任一路 ≥0.7 或 两路 ≥0.5 即拦 | 监管风险高，不能等两路都满分 |
| 低俗擦边 | 画面 + 文本联合加权 | 单看画面易误杀舞蹈健身类 |
| 版权搬运 | 视觉指纹 + 音频指纹 | 需要跨模态比对 |

**闸门 3：人审分级队列**

- P0：监管举报、涉未成年人、已在传播的高危内容——SLA 5 分钟
- P1：机审不确定（综合分 0.45–0.75）——SLA 30 分钟
- P2：抽样质检、低粉账号新发——SLA 4 小时

审核员界面按「证据聚合」设计，而不是让他们自己拖进度条找问题。

**闸门 4：上线后回扫与舆情监测**

- 已放行内容按账号风险等级做 1%–20% 不等的二次审核
- 相似内容聚类：一条被判违规，同簇内容自动提级
- 外溢监测：微博/竞品平台的同款话术回流

陈默跟林薇说：「以前我们把机审当大门，人审当后门。现在应该是五环闸门，任何一环都能独立刹车。」

### 第五章：搞不定的时候，系统怎么优雅降级

除夕夜 23:40，峰值来了。上传 QPS 冲到平时的 12 倍，GPU 推理集群排队延迟从 200 ms 飙到 4 s。

监控告警响起：**视频机审 SLA 违约率 38%**。

工程负责人在 war room 里宣布启用降级预案，按优先级砍能力：

1. **L1 降级**：关闭非关键帧的高精度 OCR，只保留字幕轨 ASR + 封面图审核——延迟回落，但画面硬字幕漏检风险上升
2. **L2 降级**：新注册账号和近 7 日违规账号的内容，同步机审改为「先审后发」；老账号高信誉内容维持原策略
3. **L3 降级**：机审超时（>5 s 无结果）的内容**默认进人审池，不默认放行**——这是上次事故后林薇亲自批的红线
4. **L4 降级**：启动「仅文本 + 封面」粗审模式，视频全量审核延迟到离线——话题活动页面临时下线「自动上推荐流」，只进关注页

陈默在方案评审里写过降级，但第一次见真降级，才发现**产品文档里没写清楚的每一档，现场都会变成扯皮**：运营说 L2 会影响 KOL 体验，算法说 L1 会导致 OCR 召回下降。

最后林薇拍板：春节峰值可以接受「少推一点」，不能接受「漏一条医疗虚假宣传」。当晚执行 L2 + L3，未再出现同步放行导致的漏网。

### 第六章：成本账算清楚，才知道「全量高精审」是幻觉

活动结束后的复盘会上，财务同学要陈默回答：「多模态审核到底花多少钱，省了多少人？」

陈默摊开一张账：

**计算成本（以当晚 240 万条内容为例）**

| 模块 | 单条成本（估） | 量级 | 说明 |
|-----|--------------|------|------|
| 图像关键帧 CV | ¥0.003 | 每视频 8 帧 | 峰值时可降采样 |
| OCR | ¥0.002 | 每帧 | 最贵的一路之一 |
| ASR | ¥0.008 | 每分钟音频 | 长视频成本陡增 |
| 文本分类 | ¥0.0003 | 每段文本 | 相对便宜 |
| 人审 | ¥0.15–0.8 | 每条 | 取决于复杂度与外包单价 |

如果 240 万条全走最高规格机审 + 10% 人审，当晚成本接近 ¥200 万级——业务不可能接受。

真实策略是**风险分层**：

- 约 82% 内容机审低危直接放行（成本 ¥0.01/条以内）
- 约 14% 进人审（成本主要在这里）
- 约 4% 同步拦截

陈默在会上说了一句话，后来被写进团队 wiki：「审核系统的商业本质，是在**漏放成本**和**误杀成本**之间找平衡点，而不是追求 100% 自动化。」

漏放一条虚假医疗视频，监管处罚 + 品牌损失 + 紧急公关，可能是百万级；误杀一条普通年夜饭视频，是一个用户投诉和 ¥5 红包。两者的**不对称风险**，决定了融合策略必须偏保守，且保守的方式是「不确定就送人审」，不是「不确定就放行」。

# 3. 系统正解

这个系统的核心是**多模态内容审核流水线**：用户上传的图文/短视频/直播流，被拆成画面、画面文字（OCR）、语音转写（ASR）、标题描述等多个「信号通道」，各路 AI 模型并行打分后，由**融合决策引擎**（规则 + 加权策略 + 场景策略）输出「放行 / 拦截 / 送人审」三态；高风险或低置信内容进入**分级人审工作台**，审核员看到的是多模态证据聚合面板而非原始素材；全链路配有**同步 SLA 闸门、峰值降级、上线后回扫与相似内容聚类**，确保机审超时或算力不足时默认更安全的一侧。

回扣故事：陈默复盘的那条漏网视频，对应「CV 弱信号 + OCR 错字 + ASR 高危 + 标题异步」四个模块的衔接裂缝；小周 40 秒结案对应「人审证据面板」；当晚 L2/L3 降级对应「超时默认送人审、新号先审后发」；财务复盘对应「分层审核的成本结构」。

**AI 产品岗典型应用场景：**

- **需求文档**：写清每类内容（图文/短视频/直播）的审核链路、同步/异步边界、三态处置枚举（放行/拦截/人审），避免只写「接入 AI 审核」
- **方案评审**：挑战「单模态高分不拦截」是否合理，要求给出分场景融合表和误杀/漏放案例
- **指标设计**：同时看「漏放率」「误杀率」「人审 SLA」「机审 P99 延迟」「单位审核成本」，禁止只报「自动化率 90%」
- **跨团队沟通**：跟算法对齐「OCR 错字、ASR 方言、弱信号帧」的已知缺陷；跟运营对齐峰值降级时哪个活动入口要收缩；跟法务对齐审计日志保留哪些证据字段

# 4. 类比锚定

## 旧知 → 新知：机场安检

传统 PM 都经历过机场安检：行李过 X 光、人过金属探测、可疑物品开箱人工检查、不同航班/旅客等级走不同通道、高峰期加开人工口、极端情况提高安检等级。

多模态内容审核，就是 UGC 平台的「安检系统」——只不过受检的不是行李，而是用户上传的图文视频；安检仪器的角色由 CV、OCR、ASR、文本模型分担；开箱检查就是人审证据面板。

| 你熟悉的旧经验（机场安检） | 多模态内容审核系统 |
|---------------------------|-------------------|
| 行李 X 光机 | 视频关键帧 CV 模型、图像分类 |
| 液体/充电宝单独检查规则 | 特定类目专项模型（医疗、金融、未成年人） |
| 开箱人工检查 | 分级人审工作台 + 多模态证据聚合 |
| 安检通道分级（普通 / 易检 / 要客） | 账号信誉分级、同步审 / 异步审、先发后审策略 |
| 高峰期限流、加开人工口 | 峰值降级、算力排队、人审 SLA 扩容 |
| 禁运品名录 | 违禁词库、黑名单、监管红线类目 |
| 安检超时不能默认放行 | 机审超时默认送人审或拦截，绝不静默放行 |
| 同行行李关联检查 | 相似内容聚类、矩阵号同簇提级 |

# 5. 类比边界与系统要点

## 类比在哪里会失效

机场安检面对的对象是物理物品，类型有限、边界清晰；UGC 内容是用户刻意对抗审核的「软物体」——换错别字、插入一帧、用方言口播、把违规信息放在画面角落。**审核对抗（Adversarial）**和**多模态语义融合**，是机场类比天然覆盖不了的。

## A. 系统核心要点总结

- **数据输入要求与格式规范**：不同模态对素材格式、分辨率、时长、编码有要求；上传端需统一抽帧策略、音频采样率、标题与本体绑定 ID，否则多路结果无法在同一决策窗口融合。
- **AI 模型的能力边界与置信度**：OCR 怕错字/艺术字，ASR 怕方言和 BGM 干扰，CV 怕遮挡和快速剪辑；任何单路模型都不能当「最终法官」，必须输出置信度供融合层使用。
- **人工介入的触发条件与流程**：低置信融合分、单路高危但规则要求复核、用户举报、相似违规聚类、新账号首发——都应有明确入池条件和人审 SLA，不能依赖审核员「自己刷到」。
- **系统的容错与降级机制**：算力不足时按风险砍能力（降采样、关 OCR、缩回推荐流），但**超时默认更安全一侧**；降级档位需提前与运营、法务签字，不能现场临时发明。
- **成本结构**：GPU 推理（按帧/按时长）、存储（证据留存）、人审（按条/按复杂度）、漏放纠错（下架、公关、监管）——四笔账要一起算；「全量最高规格机审」在真实业务里通常不存在。

## B. 类比失效点

1. **安检物品不会自己改包装，违规内容会主动对抗**：用户会用谐音、拆帧、镜像、AI 换脸等方式绕过单路检测；产品必须规划对抗迭代，而不是一次上线就结束。
2. **机场安检误杀代价相对对称，内容审核误杀与漏放极度不对称**：误杀一条正常年夜饭视频是一个投诉；漏放一条虚假医疗可能引发监管处罚。融合策略不能照搬「疑罪从无」。
3. **多模态不是简单叠加**：「画面正常 + 语音违规 + 标题导流」的组合风险，大于任何单路分数之和；机场安检里「刀在箱子里」是明确关联，而图文视频的违规语义可能分散在不同模态。
4. **AI 输出是概率性的，需要持续迭代**：新话术、新视觉风格、新平台梗每周都在变；词库、样本库、模型版本是运营资产，要配套灰度、回滚、A/B 和漏放复盘闭环。
5. **合规与审计要求远超安检记录**：需保留「当时用了哪个模型版本、各路人马分、谁做人审、依据哪条规则」——监管检查和诉讼举证时，黑盒「系统说没问题」不被接受。

# 6. 深度业务洞察

1. **业务侧：表面要「秒级上线」，真实要「可控漏放」**  
   运营常推动「先发后审」以换春节 GMV 和话题热度，但医疗、未成年、涉政类目不能有异步窗口。PM 要做的不是简单拒绝运营，而是把「哪类内容可以异步、哪类必须同步」写成可配置的红线表，并让漏放责任链可追溯。

2. **技术侧：最难的不是单模型准确率，是多模态融合与时序**  
   四路模型各自 90% 准确率，融合后漏放率可能仍高于预期——因为错字 OCR、帧采样遗漏、标题与视频不同步到达。工程上「证据对齐时间轴」和「决策等待窗口」往往比再训一个模型更关键。

3. **运营侧：人审是产能瓶颈，界面设计决定人效**  
   审核员每秒处理量取决于是否预聚合证据、是否自动跳转到高危帧、是否有快捷键和案例库。把人审当「廉价劳动力」而不做产品化工具，会导致旺季无限加人仍赶不上队列。

4. **合规侧：证据留存与可解释性是上线前提**  
   下架一条视频容易，向监管说明「为何当时放行」难。需保留模型版本、分数、规则命中、人审记录至少 6 个月（具体以行业为准）；跨境业务还要面对不同法域对「仇恨言论」「隐私人脸」的不同定义。

5. **商业侧：ROI 要算「漏放损失」而不是只算「省了多少审核员」**  
   对外卖审核能力时，客户最关心的是「漏放率 + SLA + 行业适配」；对内要算峰值算力租赁、人审外包、误杀带来的创作者流失。ToB 审核 SaaS 的定价常按「调用量 + 人审条数 + 专项类目」组合，而不是单一 API 单价。

### 动手小练习（30 分钟）

**练习：设计一条「短视频」的多模态审核决策表**

1. 选一个你熟悉的内容平台场景（社区、电商买家秀、直播切片均可）；  
2. 列出 4 类红线（如导流、医疗宣称、低俗擦边、搬运）；  
3. 为每类红线写清：画面 / OCR / ASR / 标题 四路信号里，「单路拦截条件」和「融合拦截条件」分别是什么；  
4. 设计一档峰值降级：先砍哪一路、超时默认「送人审」还是「拦截」。

完成后自问：如果 OCR 把「见效」识别成「见笑」，你的表还能拦住吗？如果不能，人审面板该补什么证据？——那就是你下一份 PRD 该写的「已知缺陷兜底」。
