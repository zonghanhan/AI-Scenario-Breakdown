# 2. 业务场景故事

## 《续保到期前三天，那通把 VIP 客户怼挂了的「智能」电话》

### 第一章：续保名单下来了，外呼任务开始排队

3 月 12 日周一早上 8:30，安泰人寿续期部的季度冲刺进入倒计时。未来 72 小时内，有 4.2 万份保单到期，其中 1.1 万份尚未确认续保意向。

续期主管老周给刚转行做 AI 产品的林晓下了死命令：「去年这时候，200 个坐席从早打到晚，接通率 38%，人均每天有效通话 47 通。今年你上了智能外呼，我要求同样人力下，有效触达翻倍——但有一条，**VIP 客户名单上的 860 人，不许用机器人直接怼。**」

林晓信心满满。过去两个月，她和语音算法、呼叫中心工程搭了一套「智能外呼系统」：系统按名单自动拨号，机器人先开口介绍续保方案，识别客户意图后走不同话术分支，能自助办理的引导到短信链接，搞不定的转人工坐席。

上线首日，仪表盘看起来不错：

- 自动外呼量：3,800 通/天
- 机器人独立办结率：41%
- 转人工率：22%
- 平均通话时长：1 分 48 秒

老周在群里发了个「👍」，然后补了一句：「下午我陪你去听听录音，别光看数字。」

**悬念**：林晓以为智能外呼的核心是「话术写得好不好」，很快她会意识到，真正要命的是「这通电话该不该打、什么时候打、客户一翻脸系统来不来得及收」。

### 第二章：一通电话拨出去，系统其实在并行做六件事

下午 14:17，系统拨出了第 2,847 通电话。对方是客户「陈先生」——年缴保费 3.8 万、连续投保 6 年、标签为「VIP + 高价值 + 历史投诉 1 次」。

林晓戴上耳机听实时监听。电话响了三声，陈先生接了：「喂？」

机器人开口：「陈先生您好，我是安泰人寿智能服务助手，您名下『安康福终身重疾险』将于 3 月 15 日到期，请问您——」

陈先生打断：「又是你们？上次理赔拖了两个月，现在还打电话推销？」

**此刻，系统在后台并行跑六条链路：**

**链路 1：拨号与线路调度（工程为主）**

外呼任务从 CRM 名单池取出陈先生号码，经过「线路商轮询 + 归属地匹配 + 并发限流」后拨出。当前时段（14:00–17:00）配置的最大并发是 180 路，陈先生这通排在第 47 批。

问题出在名单导入：陈先生的「历史投诉」标签写在备注字段里，导入外呼名单时**只读了主表 VIP 标识，没读备注**，所以他没有被划入「人工优先触达」白名单。

**链路 2：ASR 实时听写（AI 介入）**

ASR（自动语音识别，把人说的话转成文字）每 200 毫秒出一帧转写结果：「又是你们」「上次理赔拖了两个月」「现在还打电话推销」。

情绪识别模型给出「愤怒」标签，置信度 0.83。但当前话术配置里，**情绪触发转人工的阈值是 0.9**——因为上周测试时 0.85 误触发太多，运营要求调高。

**链路 3：NLU 意图识别（AI 介入）**

NLU（自然语言理解，判断用户想干什么）同时输出多个意图：

| 意图 | 置信度 | 系统动作 |
|------|--------|---------|
| 拒绝沟通/挂断 | 0.76 | 应走「致歉 + 挽留」分支 |
| 投诉历史理赔 | 0.71 | 应转人工或触发致歉话术 |
| 询问续保 | 0.12 | 当前默认分支 |

对话管理器（DM，决定机器人下一句说什么的模块）选了置信度最高的「拒绝沟通」分支，播放话术：「陈先生，续保可享 8% 保费优惠，错过需重新核保——」

**链路 4：TTS 语音合成（AI 介入）**

TTS（文本转语音）把上面那句话合成为女声播报。陈先生听到的节奏平稳、没有停顿——在愤怒客户听来，像「根本没在听我说话」。

**链路 5：合规规则引擎（规则为主）**

规则引擎检查：当前时间 14:17，在允许外呼时段（9:00–20:00）内 ✓；陈先生近 7 日未被呼叫 ✓；号码在黑名单 ✗。

但「近 30 日有未结案投诉」这条规则**没有接入外呼前拦截**——投诉系统与 CRM 的数据同步是 T+1，陈先生上周的投诉状态还没写回。

**链路 6：人工坐席池与转接（人机协作）**

陈先生吼了一句「再打来我就换公司」，然后挂断。系统记录「客户主动挂断」，结案原因码：BUSY_HANGUP。

全程没有触发转人工——因为转人工的触发条件是「客户明确说转人工」或「情绪 > 0.9 且意图为投诉」，两个条件都没满足。

林晓摘下耳机，发现老周就站在身后，脸色不太好看：「你猜他会不会投诉？」

### 第三章：「我要投诉」三个字，转人工却等了 47 秒

当晚复盘，团队拉出同一天 17 通「VIP 客户挂断」录音，模式惊人地一致：

1. 机器人开场白太长（平均 18 秒），客户没耐心听完；
2. 客户提到「理赔」「投诉」「别打了」，系统识别到了，但阈值设太高没触发转人工；
3. 触发转人工的 63 通里，**平均等待 47 秒**——客户早就挂了。

工程同学解释转接慢的原因：

- 外呼是「机器人占一条线路，转人工需要再拨坐席分机」，不是呼入场景的天然桥接；
- 坐席池按「当前空闲」匹配，但 14:00–15:00 是续期部开会时段，实际空闲坐席比系统显示少 30%；
- 转接提示音还是机器人播报：「正在为您转接人工服务，请稍候」——又多了 8 秒。

老周在白板前画了一条线：「智能外呼不是『把电销员换成喇叭』。客户接起电话的那一刻，你们只有 **8 秒黄金窗口**——8 秒内没对上话，后面全是噪音。」

团队当场拍板了三条改动，后来都成了产品里的标准配置：

1. **VIP/投诉客户外呼前拦截**：名单入库前做「投诉状态 + VIP 等级 + 近 30 日接通频次」三维校验，命中则只进人工任务池；
2. **情绪 + 关键词双轨触发转人工**：「投诉」「理赔」「别打了」等词命中即转，不等情绪分数；情绪 > 0.75 且意图为拒绝时，先致歉再转，禁止继续推销；
3. **转人工 SLA ≤ 5 秒**：坐席池预留 15% 缓冲席，转接失败则机器人主动说「稍后由专属顾问回电」并创建回呼工单，而不是让客户干等。

林晓在 PRD 里加了一行红字：**转人工不是兜底，是 VIP 场景下的默认路径之一。**

### 第四章：接通率涨了，投诉率也涨了

改动上线一周后，数据出现「好看又难看」的分化：

| 指标 | 改动前 | 改动后 |
|------|--------|--------|
| 机器人独立办结率 | 41% | 36%（下降，预期内） |
| 有效触达率（通话 > 30 秒） | 52% | 61% |
| 续保意向确认率 | 28% | 34% |
| 外呼相关投诉量 | 12 件/周 | 4 件/周 |
| 单次外呼成本（含线路+算力+人工） | ¥1.42 | ¥1.67 |

老周说：「独立办结率下降不是坏事，说明你把不该机器人扛的单子放出去了。」

但财务同事追问：「单次成本涨了 17%，年底 ROI 怎么报？」

林晓和运营一起算了笔账：

- **节省**：同样 200 坐席，人工外呼量从日均 9,400 通降到 6,200 通，坐席可腾挪去做高客单价跟进；
- **新增**：ASR+TTS+NLU 推理费用 ¥0.23/通；投诉拦截带来的「客户挽留」——陈先生那类如果流失，单客 LTV（生命周期价值）损失远超 ¥1.67；
- **隐性成本**：话术迭代、录音质检、合规审计，每月固定 2.5 万人力成本，不能漏算。

更关键的是**外呼时段策略**的调整。数据分析发现：

- 9:00–11:00 接通率最高（44%），但「我在开会」挂断率也高；
- 18:30–19:30 接通率只有 31%，但意向确认率最高（41%）；
- 午休时段（12:00–13:30）外呼，投诉率是其他时段的 2.3 倍。

系统从「统一时段批量外呼」改成「按客户画像推荐时段 + 失败重拨策略」：

- 企业主标签 → 优先 12:30、18:30；
- 退休标签 → 优先 9:30、15:00；
- 连续 2 次未接 → 停呼 72 小时，改短信触达。

这不是算法多高级，是 PM 把「什么时候打」当成了和「说什么」同等重要的产品参数。

### 第五章：话术不是写完就完，是持续做 A/B 的「活资产」

月底，林晓组织了一场「话术听证会」——销售、合规、客服、算法四方坐一起，逐句过机器人脚本。

争议最大的一句：「错过本次续保，需重新核保，可能面临加费或拒保。」

- 销售说：这是促单利器，去掉转化率掉 15%；
- 合规说：「拒保」表述不严谨，容易引发监管投诉；
- 客服说：客户听到这句，80% 会先问「我是不是买不了了」，机器人答不好就炸；
- 算法说：这句话后面 3 轮的 NLU 意图识别准确率只有 62%，因为客户问题太发散。

最终改成两个版本做 A/B 测试：

- **版本 A（强促单）**：保留原句，但触发后 3 秒内必须提供「转人工了解详情」入口；
- **版本 B（温和）**：「续保窗口即将关闭，专属顾问可为您评估保障方案」。

跑了两周，版本 B 的意向确认率低 6%，但投诉率低 71%，转人工后的成交率反而高 12%。全量切到版本 B。

林晓在复盘文档里写：**智能外呼的竞争力，不在「机器人多像人」，而在「什么人打、什么时候打、说什么、何时收、搞不定交给谁」这五件事有没有被设计成可配置、可度量、可回滚的系统能力。**

系统最终保留的人工介入点：

- **外呼前**：VIP、投诉未结案、黑名单、近 7 日已接通 → 不自动外呼；
- **通话中**：关键词/情绪/意图三重触发转人工；机器人连续 2 轮 NLU 置信度 < 0.6 → 主动致歉并转接；
- **通话后**：客户标记「强烈拒绝」→ 90 天内进入禁呼名单；未接通的按画像时段重拨，最多 3 次；
- **事后优化**：每周从「挂断点话术 × 客户标签」反推脚本迭代优先级，质检抽检比例不低于 5%。

老周在季度汇报上对老板说：「智能外呼不是裁员的刀，是把坐席从『拨号机器』变成『签单顾问』的铲子。」

# 3. 系统正解

这个系统的核心组件和数据流可以概括如下：

**名单入库与合规校验 → 拨号调度 → ASR 实时听写 → NLU 意图识别 → 对话管理（话术分支）→ TTS 播报 → 转人工/自助办结/回呼工单 → 录音存档与质检回写。**

回扣故事：陈先生那通电话，对应「名单导入漏读投诉标签」和「外呼前拦截未生效」；机器人继续推销优惠，对应「情绪阈值过高 + DM 选了错误意图分支」；转人工等 47 秒，对应「外呼转接链路长 + 坐席池状态不准」；话术 A/B 测试，对应「NLU 准确率和合规风险的联合优化」。

在 AI 产品岗的典型应用场景：

- **需求文档**：不只写「AI 自动外呼」，要写清名单字段（VIP、投诉、禁呼）、时段策略、转人工触发条件、失败重拨规则、录音留存期限。
- **方案评审**：当业务方要求「100% 机器人外呼、零人工」时，用 VIP 投诉案例和单次客户流失 LTV 反问——「这通搞砸了，赔得起吗？」
- **指标设计**：同时看接通率、有效触达率、独立办结率、转人工率、投诉率、续保转化率；单一追求「机器人办结率」会鼓励系统硬扛本该转人的对话。
- **跨团队沟通**：跟算法说「这句关键词命中必须 100% 触发，不能靠概率」；跟工程说「外呼转人工的 SLA 和呼入不同，要单独测」；跟合规说「哪些话术要预审、哪些时段绝对禁呼」。

# 4. 类比锚定

## 旧知 → 新知：传统电销中心的「班长盯线 + 话术本」

做过 ToB 或金融业务的 PM，多少见过电销中心：名单下发 → 班长分配线路 → 坐席按话术本开口 → 客户反抗时班长耳机里提醒「换脚本」或「换老手接」。

智能外呼，就是把「班长 + 话术本 + 拨号器」编码成一套可配置系统——但班长并没有消失，而是变成了「规则引擎 + 质检 + 人工池调度」。

| 你熟悉的旧经验 | 智能外呼系统 |
|---------------|-------------|
| 今日拨打名单 | CRM 外呼任务池 + 合规过滤后的可拨名单 |
| 班长分配哪条线 | 拨号调度器（并发控制、线路轮询、时段策略） |
| 话术本第 3 页第 2 段 | 对话管理器里的话术分支节点 |
| 客户说「别打了」 | ASR 转写 + NLU 意图识别 + 关键词规则 |
| 班长举手换老手接 | 转人工触发 + 坐席池匹配 + 回呼工单 |
| 通次日报表 | 接通率、办结率、投诉率、单次成本看板 |
| 质检员抽听录音 | 录音存档 + AI 质检 + 人工复核 |

# 5. 类比边界与系统要点

## 类比在哪里会失效

电销中心里，班长能「听语气」决定要不要抢线；机器人只能依赖 ASR 转写和模型分数，**听不出叹气里的愤怒，也分不清讽刺和同意**。这是「班长盯线」类比覆盖不了的能力边界。

## A. 系统核心要点总结

- **数据输入要求与格式规范**：外呼效果高度依赖名单质量——VIP 标识、投诉状态、历史接通、禁呼标签必须在拨号前一次性校验；字段散落在备注里、同步延迟 T+1，都会让「智能」变成「智障」。
- **AI 模型的能力边界与置信度**：ASR 在口音、噪音、抢话场景下会出错；NLU 对「我不是那个意思」类否定句识别率偏低。低置信度时不应继续推销，而应致歉 + 转人工或主动结束。
- **人工介入的触发条件与流程**：VIP、投诉、关键词、情绪、连续低置信——触发条件要写进配置，不能靠运营「记得盯」；转人工 SLA 必须单独定义，外呼场景比呼入更难做无缝转接。
- **系统的容错与降级机制**：转人工失败 → 承诺回呼 + 创建工单；客户挂断 → 按画像改时段重拨；合规拦截 → 整批名单熔断。每条降级路径要有明确结案码，方便复盘。
- **成本结构**：线路费 + ASR/TTS/NLU 推理费 + 坐席人工 + 投诉赔偿 + 话术运营与质检，五笔账要一起算；机器人办结率每提高 1%，可能是多扛了 1% 的投诉风险。

## B. 类比失效点

1. **电销坐席能即兴发挥，机器人只能走分支**：客户问「我上次理赔到哪了」，坐席可以查系统边聊；机器人若没有对接业务 API（工具调用），只能机械重复话术，体验断崖式下跌。
2. **外呼是主动打扰，合规约束远比呼入严**：电销中心有「时段 + 频次 + 明示身份」要求，智能外呼还要处理录音授权、退订机制、行业黑名单——班长盯线类比不会提醒你这些硬约束。
3. **AI 系统需要持续迭代**：话术、意图、客户反抗表达方式每季度都变；上周调的 0.9 情绪阈值，这周可能就误杀大量正常客户。**概率性输出必须配合 A/B 测试和回滚机制**，不能像话术本一样「印一版用一年」。
4. **「像人」不是目标，「办成事或优雅收场」才是**：过度追求 TTS 自然度，可能让客户误以为是真人，反而引发「欺骗感」投诉；产品要在开场白里明确「我是智能助手」。
5. **外呼失败也有价值**：未接通、秒挂、拒接都是信号，应回写客户画像优化下次触达——电销类比容易让人只关注「接通的」，忽略「没接通的为什么」。

# 6. 深度业务洞察

1. **业务侧：表面要「省人力」，真实要「在对的时刻说对的话」**  
   业务方常把 KPI 写成「机器人替代 80% 人工外呼」，但真正影响续保率的是「谁在什么时候被打、第一句话是什么」。陈先生那种 VIP，不打比打错更好。PM 要推动把「禁呼规则」和「外呼策略」放在需求优先级最前面，而不是话术优化。

2. **技术侧：ASR+NLU 链路延迟是体验杀手**  
   客户说完到机器人接下一句，行业理想值 < 1 秒，超过 2 秒就会有「你在吗」的错觉。很多项目 ASR 准确率在实验室 95%，现场只有 82%——因为外呼场景有街道噪音、免提回声、老人语速慢。PM 要在方案里定义「现场验收标准」，不能只看实验室报告。

3. **运营侧：话术是「产品」，不是「文案」**  
   每句话都要对应 NLU 能接住的意图分支；一句「可能拒保」后面如果没有准备好的 3 轮问答，就是埋雷。话术迭代必须和 NLU 训练数据同步更新，否则会出现「脚本改了、模型还按旧意图走」的割裂。

4. **合规侧：外呼是监管高发区**  
   时段限制、频次限制、明示身份、退订机制、录音授权——金融、保险、教育行业各有细则。一次违规外呼的罚款和客户投诉，可能抵消一万通机器人节省的成本。PM 要把合规规则做成「拨号前硬拦截」，而不是「话术里加一句免责声明」。

5. **商业侧：ROI 要算「客户流失」而不只是「人力节省」**  
   智能外呼的单次成本通常比纯人工低，但误触高价值客户导致的流失、投诉升级、品牌损伤，在账本上往往被漏掉。建议按客户分层算账：普通名单追求办结率，高价值名单追求体验，两套策略两套 ROI。

### 动手小练习（30 分钟）

**练习：设计一通「续保提醒」外呼的决策表**

1. 假设你是林晓，列出 5 类客户标签（普通、VIP、投诉未结案、连续未接、明确拒接）；  
2. 为每类写清：能不能自动外呼、首选时段、开场白前 8 秒说什么、什么条件下转人工；  
3. 设计 3 个「机器人必须闭嘴」的关键词及系统动作；  
4. 定义 1 个转人工失败的降级方案。

完成后自问：如果陈先生的「历史投诉」标签写在备注里、主表没有，你的决策表能拦住这通电话吗？如果不能，名单入库环节该加什么校验？
