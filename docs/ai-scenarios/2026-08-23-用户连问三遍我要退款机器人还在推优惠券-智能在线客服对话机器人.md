# 2. 业务场景故事

## 《用户连问三遍「我要退款」，机器人还在推优惠券》

### 第一章：大促零点，机器人先顶上

6 月 18 日 00:07，云杉电商 App 的在线客服入口，同时在线用户从 1,200 人飙到 8,600 人。人工坐席 320 人在线，平均排队时长已经 11 分钟。

值班产品周航盯着大屏上的三条曲线：机器人接待占比 73%、机器人独立办结率 38%、转人工率 41%。老板在群里问：「比去年好了吧？」周航回了个「👍」，心里却在打鼓——上周灰度测试时，独立办结率明明是 52%。

零点刚过 20 分钟，客服主管赵敏甩过来一条内部反馈截图。用户「林女士」的聊天记录：

> **林女士**：我买的空气炸锅收到是坏的，要退款  
> **机器人**：亲，618 大促满 300 减 50 优惠券还没用完哦，要帮您看看适用商品吗？  
> **林女士**：我说要退款！！！  
> **机器人**：为您推荐三款热销空气炸锅，现在下单享分期免息～  
> **林女士**：转人工  
> **机器人**：当前排队人数较多，预计等待 8 分钟。您可以先描述问题，我来帮您～  
> **林女士**：退款退款退款  
> **机器人**：好的，已为您记录「价格咨询」，请稍候

林女士在 00:14 给了差评，截图发到了微博。赵敏只问了一句：「你的机器人，到底在跟谁说话？」

**悬念**：周航以为对话机器人的核心是「知识库全不全」，很快他会发现，真正要命的是「用户这句话，系统到底听成了什么、敢不敢办事、转人工转不转得出去」。

### 第二章：一条用户消息进来，系统其实在并行做六件事

周航拉着 NLU 算法、对话工程、知识库运营做了一条消息的端到端复盘。林女士第一句「我买的空气炸锅收到是坏的，要退款」，时间戳 00:11:23。

**此刻，系统在后台并行跑六条链路：**

**链路 1：会话接入与渠道识别（工程为主）**

用户从 App「我的订单」页点进客服，系统自动带上上下文：订单号 OD202506180047、商品「云杉 Pro 空气炸锅 5L」、订单状态「已签收」、签收时间「6 月 17 日 18:42」、用户等级「普通会员」、当前大促标签「618」。

这些字段本应在后续对话里被机器人直接引用，而不是让用户重复报单号。但周航发现，**订单状态「已签收」没有写入对话管理器的初始槽位**——机器人开场白是通用促销话术，上下文丢了。

**链路 2：NLU 意图识别 + 槽位抽取（AI 介入）**

NLU（自然语言理解，判断用户想干什么并提取关键信息）输出：

| 字段 | 识别结果 | 置信度 |
|------|---------|--------|
| 主意图 | 商品推荐/促销咨询 | 0.64 |
| 次意图 | 售后/退款 | 0.58 |
| 商品实体 | 空气炸锅 | 0.91 |
| 问题类型 | 未识别「质量问题」 | — |
| 情绪 | 中性 | 0.72 |

「要退款」被拆成了两个词：「退」命中了促销话术里的「退换货政策」词条，「款」没接上完整意图。更麻烦的是，**推荐模型和大促运营配置了一个高权重意图「618 优惠券引导」**，在 0.55–0.70 的模糊区间里，推荐意图被强行顶上。

**链路 3：对话管理器 DM 决策（规则 + 模型）**

DM（对话管理器，决定机器人下一句说什么的模块）收到主意图「促销咨询」，走分支 B-618：推送优惠券 + 关联商品推荐。这个分支是运营上周刚上线的，目标是拉升客单价，**没有在「已签收订单 + 含退款关键词」时做拦截**。

**链路 4：知识检索 / 业务 API 调用（RAG + 工具）**

如果意图被判为「售后退款」，系统应该：

1. 调订单 API 确认签收状态与退款资格；
2. 检索知识库「质量问题退款流程」；
3. 若符合「签收 7 天内 + 质量问题」，推送「上传破损照片」引导或一键发起售后。

但因为在链路 2 就判错了意图，**业务 API 根本没被调用**。知识库不是没答案，是机器人没走到那扇门。

**链路 5：回复生成（模板 + 可选 LLM）**

当前配置是「模板话术为主、大模型润色为辅」。促销分支有固定模板，LLM 只负责把「满 300 减 50」说得更口语化，**没有权限改写分支走向**。所以林女士看到的，是逻辑自洽但完全答非所问的营销话术。

**链路 6：转人工判定（规则引擎）**

林女士第二次说「我说要退款！！！」时，情绪模型升到「愤怒」0.81，关键词「退款」命中。按理应触发转人工，但：

- 当前大促配置了「转人工排队 > 5 分钟时，先机器人挽留」策略；
- 「转人工」三个字本身被 NLU 判成「咨询如何联系客服」，置信度 0.49，低于转人工阈值 0.6；
- 系统走了「安抚 + 继续机器人接待」，并把会话标签错打成「价格咨询」。

林女士第三次怒吼时，人工坐席终于接入——此时她已经等了 9 分钟，带着一肚子火。坐席小陈花了 4 分钟重新核实订单，3 分钟走完质量问题退款流程。本可在 90 秒内办结的工单，变成了投诉 + 舆情。

**悬念**：周航意识到，对话机器人不是「会不会聊天」，而是「听不听得懂、敢不敢办事、搞不定能不能及时放手」。

### 第三章：三种「听错了」，对应三种不同的产品修法

复盘会上，算法同学把过去 24 小时「机器人答非所问」的案例归成三类，周航发现每一类都要不同的产品策略，不能一锅炖：

**类型 A：意图识别错了（听岔了）**

典型表现：用户说退款，机器人推优惠；用户问物流，机器人答发票。

修法：

- 在模糊置信区间（如 0.5–0.75）**不要强行选最高分意图**，而是走澄清话术：「您是想办理退款，还是想了解优惠活动？」
- 把「订单状态 + 用户关键词」做成**前置规则**：已签收 +「坏了/破损/退款」→ 强制进入售后意图，覆盖模型输出。
- 建立「对抗样本」集：把大促期间真实骂机器人的话喂回训练，每周滚动更新。

**类型 B：意图对了，但不敢办事（不敢办）**

典型表现：机器人说「请前往订单页申请售后」，用户说「我就是在订单页点进来的」；机器人反复给政策原文，不帮用户点按钮。

修法：

- 区分「信息问答」和「任务办理」两种能力。后者需要对接业务 API（查订单、创建售后单、发优惠券），也就是 Agent 场景里的**工具调用**。
- 产品上要定义「机器人自主办理」的权限边界：金额 < 500 元 + 质量问题 + 有图，可自动创建售后单；超过阈值转人工。
- 每多一项「能办的事」，都要配一条「办错了怎么回滚」的降级路径。

**类型 C：该转人工没转，或转不出去（转不出）**

典型表现：用户明确说转人工，机器人还在背 FAQ；转人工排队 15 分钟，用户直接流失。

修法：

- **转人工触发条件要「宁多勿少」**：关键词（转人工、投诉、律师）、情绪阈值、连续 2 轮意图低置信、VIP 标签——满足任一即转，不要用「AND 逻辑」卡太死。
- 转人工不是终点，要同步**工单预填**：把 NLU 已识别的意图、订单号、对话摘要推给坐席，避免用户第三遍复述问题。
- 排队过长时的降级：短信/ App Push 回呼、留言工单、预估回呼时间——比「请您继续跟机器人聊」体面得多。

赵敏听完只说：「下周机器人独立办结率我不看绝对值，先看**答非所问率**和**转人工后重复陈述率**。」

### 第四章：人机协作——机器人的「决策权限」到底画在哪

周航重新画了一张「对话机器人决策权限表」，这是 PM 在方案评审里最该拿出来的一张图：

| 场景 | 机器人可自主 | 需用户确认 | 必须转人工 |
|------|------------|-----------|-----------|
| 物流查询 | 查物流并播报 | — | — |
| 7 天内无理由退 | 引导填单 | 确认退款金额 | 金额 > 2000 元 |
| 质量问题退 | 收图 + 创建售后单 | 确认商品状态 | 用户威胁投诉 |
| 价保/退差价 | 计算差额 | 确认是否申请 | 规则争议 |
| 优惠券未到账 | 查发放记录 | — | 系统异常 |
| 情绪愤怒 + 任意售后 | — | — | 立即转 |

核心原则三条：

1. **能查的不让用户查，能办的不让用户办**——但办之前要把关键信息复述给用户确认。
2. **模型不确定就澄清，规则不满足就转人**——不要用营销 KPI 绑架用户体验。
3. **转人工不是失败，是设计的一部分**——转得好（带上下文、低等待），比硬撑办结率更省钱。

工程负责人补了一句：「你这张表，每一条都要变成 DM 里的可配置规则，别写进 PPT 就完事。」

### 第五章：异常与降级——机器人「搞不定」时怎么办

上线第三周，云杉做了一次「故障演练」，模拟三种异常，周航发现之前 PRD 里只写了 happy path：

**异常 1：NLU 服务超时（> 800ms）**

降级策略：不走促销默认分支，改播「当前咨询人数较多，我先帮您查订单」+ 强制调订单 API 用规则兜底。宁可回复慢一点，也不能随机推优惠券。

**异常 2：知识库检索为空**

降级策略：明确告知「这个问题我需要帮您转接专员」，同时记录「未覆盖问题」写入运营 backlog，而不是让 LLM 自由发挥编造政策。

**异常 3：业务 API 返回「订单状态异常」**

降级策略：不反复让用户重试，直接转人工 + 生成工单，附带 API 错误码供坐席排查。

每条降级都要有**用户可见话术**和**后台结案码**，否则复盘时只能看到「用户不满意」，不知道卡在哪一环。

### 第六章：两周迭代后，办结率回来了——但算法变了

两周后，周航用同一套口径重看数据：

| 指标 | 迭代前 | 迭代后 |
|------|--------|--------|
| 机器人独立办结率 | 38% | 49% |
| 答非所问率（抽检） | 17% | 6% |
| 转人工率 | 41% | 36% |
| 转人工后平均首响时长 | 4.2 分钟 | 1.1 分钟（有预填摘要） |
| 大促客诉率（机器人相关） | 0.8% | 0.3% |

注意：独立办结率没有回到 52%——因为团队主动**砍掉了 3 条高风险促销强推分支**，把该转的人工转了出去。赵敏说：「这才是正常曲线。机器人不是替人扛所有事，是替人扛**该扛的事**。」

林女士的那类会话，现在走的路径是：

1. 进线自动带入订单 + 签收状态；
2. 「坏了 + 退款」命中售后强制规则；
3. 机器人：「看到您的空气炸锅 6 月 17 日签收，方便拍一张故障照片吗？」；
4. 用户上传 → 视觉模型初判「疑似加热异常」→ 自动创建售后单；
5. 全程 78 秒，未转人工。

周航把这条路径写进了下一版 PRD 首页：**对话机器人的价值，不是让用户觉得你在聊天，而是让用户觉得事情在往前办。**

# 3. 系统正解

智能在线客服对话机器人 = **会话接入层**（带订单/用户上下文）→ **NLU 意图识别与槽位抽取** → **对话管理器 DM**（状态机 + 业务规则）→ **知识检索 RAG / 业务 API 工具调用** → **回复生成**（模板 + LLM）→ **转人工与工单预填** → **全链路日志供质检复盘**。

回扣故事：林女士进线时**链路 1 丢了订单上下文**，**链路 2 意图被促销配置劫持**，**链路 4 业务 API 未触发**，**链路 6 转人工被挽留策略拦住**——四个模块串联失效，才出现「三连退款却推优惠券」的荒诞剧。

**AI 产品岗典型应用场景：**

- **需求文档**：不只写「支持多轮对话」，要逐条定义意图清单、槽位、办理权限、转人工条件、降级话术。
- **方案评审**：问算法「模糊置信区间怎么处理」、问工程「订单上下文哪一步注入」、问运营「新促销分支有没有覆盖售后拦截」。
- **指标设计**：独立办结率、答非所问率、转人工重复陈述率、平均办单时长、机器人相关客诉率——五个指标一起看，单一办结率必被玩坏。
- **跨团队沟通**：跟算法谈 NLU 训练样本和对抗集；跟工程谈 API 超时降级；跟客服谈转人工预填字段；跟法务谈机器人自主退款的金额上限。

# 4. 类比锚定

**核心类比：对话机器人 ≈ 商场总服务台的新手导购**

传统 PM 都逛过商场：总服务台有个导购，手里有对讲机（转人工）、商户目录（知识库）、收银台电话（业务 API）。顾客问什么，他得先听懂你要买、要换还是要投诉，查能不能当场办，办不了就找专柜或值班经理。

### 类比映射表

| 商场总服务台（旧经验） | 智能在线客服对话机器人（新系统） |
|------------------------|----------------------------------|
| 顾客开口第一句话 | 用户进线消息 + 渠道带入的订单/用户上下文 |
| 导购判断「买 / 换 / 投诉」 | NLU 意图识别 + 槽位抽取 |
| 导购翻商户手册答政策 | RAG 知识库检索 |
| 导购打电话给专柜留货、开票 | 业务 API / 工具调用（创建售后单、查物流） |
| 「这个得找值班经理」 | 转人工触发 + 工单预填 |
| 大促期间塞给你的传单 | 运营配置的促销话术分支（可能跑偏） |
| 导购培训手册每月更新 | NLU 模型迭代 + 话术配置版本管理 |
| 商场广播「服务台在 B1」 | 排队提示、回呼、留言等转人工降级体验 |

# 5. 类比边界与系统要点

## A. 系统核心要点总结

- **数据输入要求与格式规范**：对话质量依赖进线上下文（订单号、状态、用户等级）是否在**第一句话之前**注入；缺了上下文，NLU 再强也是瞎猜。字段要有标准 schema，不能散落在各业务线备注里。
- **AI 模型的能力边界与置信度**：NLU 在口语、省略、反讽、多意图混合句上容易翻车；0.6 附近的置信度是「高危区」，产品必须定义澄清策略，不能默认取 top-1 意图。
- **人工介入的触发条件与流程**：转人工条件要写进配置（关键词、情绪、VIP、低置信轮次、高金额），转人工时必须同步对话摘要和已填槽位，避免用户第三遍复述。
- **系统的容错与降级机制**：NLU 超时、知识库未命中、API 异常——每条链路都要有兜底，**禁止在异常时走营销默认分支**。
- **成本结构**：NLU/LLM 推理费 + 知识库维护 + 业务 API 对接 + 人工坐席 + 答错导致的客诉与舆情；少转 5% 人工可能多 3% 客诉，账要一起算。
- **持续迭代**：用户表达方式、大促话术、平台政策每月都在变；对抗样本、坏案例复盘、A/B 测试和回滚机制是标配，不是上线后「运维偶尔调调」。

## B. 类比失效点

1. **商场导购一次只接待一个人，机器人同时接待几千人**：并发场景下 NLU 延迟、API 限流、排队策略会放大体验问题；导购类比不会提醒你「峰值容量」和「熔断」。
2. **导购有常识，机器人只有概率**：用户说「气死了」可能是吐槽快递慢，也可能是要投诉；导购能读脸色，机器人只能靠情绪和上下文规则，**概率性输出必须配置信度策略**。
3. **商场导购不会在被骂后继续塞传单——但机器人会**：运营 KPI（推荐转化率、优惠券领取率）如果被硬编码进 DM，会出现「逻辑正确、体验灾难」；这是产品权限设计问题，类比覆盖不到。
4. **对话有状态，不是一问一答**：用户先说「退款」，下一句说「算了先换货」——对话管理器要维护多轮状态；总服务台类比容易让人做成「关键词触发式 FAQ」，忽略状态机。
5. **每多一项「能办的事」，风险指数级上升**：导购帮你指路没风险，帮你直接刷退款就有资损风险；机器人对接业务 API 后，办错一单的成本远高于多聊三轮。

# 6. 深度业务洞察

1. **业务侧：表面要「省人工」，真实要「别惹怒已经不爽的人」**  
   业务方常把 KPI 写成「机器人替代 70% 人工」，但大促场景里，用户进线多半已经带着问题。林女士要的是「坏炸锅赶紧退」，不是「满 300 减 50」。PM 要敢于在需求里写「以下场景禁止推销」，并拿到业务方签字。

2. **技术侧：NLU 和 RAG 是两条线，不能只修一个**  
   很多项目知识库明明有答案，机器人还是答错——根因是意图没到检索那一步。排障时先画链路：是「没听懂」「没查到」还是「查到了但生成跑偏」？三种修法完全不同。

3. **运营侧：促销话术和售后意图是天然冲突的**  
   大促前运营会上线的「优惠券引导」「关联推荐」分支，必须在 DM 里配置**售后意图绝对优先**规则。否则算法同学背锅，其实是产品没做意图优先级表。

4. **合规侧：机器人自主办理 = 电子合同行为**  
   帮用户点退款、改地址、发补偿券，都在产生法律效力。要有操作日志、用户确认节点、金额上限和可回滚机制；出问题时能回答「谁授权的、依据什么规则」。

5. **商业侧：对话机器人 ROI 别只算「少雇几个人」**  
   要算：少转人工节省的坐席成本 − 推理与运维成本 − 答错导致的客诉赔付与流失 − 知识库与标注投入。很多项目第二年 ROI 变负，因为第一年靠硬扛办结率，客诉在第三年爆发。

### 动手小练习（30 分钟）

**练习：画一张「空气炸锅质量问题退款」的对话决策表**

1. 列出用户可能的前 3 句话（含「坏了要退」「退款」「转人工」）；
