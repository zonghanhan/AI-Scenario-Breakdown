# 2. 业务场景故事

## 《尽调截止前六小时，126 份合同还没过眼的破产红线》

### 第一章：数据室开门，尽调清单已经红了

8 月 27 日 18:00，「云栈科技」收购一家区域 SaaS 分销商「智链」的尽调进入最后 48 小时。投资总监陈默把一份 Excel 甩进项目群：「法律尽调清单 127 项，目前完成 81 项。未完成的 46 项里，有 31 项卡在『历史销售与客户合同』——智链过去五年签了 412 份，法务只人工审过 68 份。」

外聘律所合伙人老周在电话里语气很平：「我们不是不想看，是人不够。按现在速度，全部过完要 11 个工作日。你们报价截止是周五中午，逾期卖方可以单方退出。」

智链法务总监吴婷发来一个网盘链接：126 份 PDF（还有 286 份在整理），命名混乱——`合同终版.pdf`、`合同终版(1).pdf`、`2023客户A补充协议.pdf`。扫描件和 Word 导出件混在一起，有的缺签署页，有的正文和附件页码对不上。

陈默 @ 了刚从前几篇「工程派单」项目转来做法务 AI 的产品经理苏晴：「你们上半年立项的合同智能审查，今晚能不能把 126 份先跑一遍？我只要知道——有没有能让交易直接黄掉的红线。」

苏晴盯着后台灰度配置：系统覆盖「标准销售合同」「渠道协议」「NDA（保密协议）」三类模板，还没碰过「旧版 OEM 贴牌协议」这种智链特有的脏数据。她回了一句很关键的话：「能跑。但今晚出来的只能是**风险标注索引**，不是法律意见。签字和交易决策仍然要过人。」

**悬念**：苏晴答应的「先跑一遍」，到底是救命的筛子，还是给周五埋雷的安慰剂？

---

### 第二章：上传之后，系统做的第一件事不是「找风险」

苏晴把 126 份文件批量拖进审查台。界面没有立刻刷红字，而是先走**文档接入与批次编排层**——这一步和发票 OCR 的「收件检查」、工程派单的「工单标准化」是同一类逻辑：

- **文件体检**：是否加密、是否扫描件、是否缺页、是否混入了报价单和营业执照；
- **合同类型路由**：销售主协议 / 渠道返利 / 服务 SLA / 劳动合同 / NDA 走不同审查 Playbook（审查剧本，就是「这类合同该查什么」的清单）；
- **版本去重**：`合同终版.pdf` 和 `合同终版(1).pdf` 全文相似度 97%，系统合并为同一「合同族」，只标「待确认主版本」；
- **优先级排队**：金额 > 500 万、含「连带责任」「独家」「对赌」关键词的排进 P0 快车道。

三分钟后，批次状态从「解析中」变成「126 份中 118 份可审查，8 份待人工拆包」。那 8 份是：3 份密码保护、2 份纯图片无文字层、3 份把六份合同订在一个 PDF 里没目录。

吴婷在群里问：「所以它还没开始找雷，先在做分拣？」

苏晴点头：「和派单前要先搞清楚工单类型一样。合同结构没理清，后面的大模型（用大段上下文理解文字的 AI）只能瞎标——把附件里的管辖条款当成正文，比不标更危险。」

**悬念**：118 份进了审查队列，真正吃算力的环节，这时才开始。

---

### 第三章：批量标注跑完，七个 P0 红灯，但有两个是「纸老虎」

系统对 118 份合同并行跑三条线：

1. **条款切分（Clause Segmentation）**：按「第 X 条」「第 X.Y 款」切成条款块，并建立交叉引用——正文写「按附件二 SLA 执行」，会链接到附件二对应段落；
2. **关键信息抽取**：付款节点、自动续约、赔偿上限、数据归属、争议管辖、独家条款等抽成结构化字段；
3. **风险识别与偏离比对**：对照云栈收购红线库 + 智链历史纠纷案例，给每条打风险等级，并和标准模板 diff。

凌晨 1:14，批次报告出炉：**7 个 P0 红灯、29 个 P1 黄灯、412 个 P2 绿点**。陈默冲进会议室：「P0 都是什么？」

苏晴投屏：

| P0 | 系统判断 | 来源合同 | 条款位置 |
|----|----------|----------|----------|
| 1 | 我方承担**无限连带责任**（渠道库存回购） | 2021-华东渠道框架协议 | 第 9.3 条 |
| 2 | 客户可单方终止 + 未使用服务费全额退还 | 某省政务云续费合同 | 第 5.1 条 |
| 3 | 知识产权归属客户，含二次开发成果 | 定制开发项目 | 附件四 2.2 |
| 4 | 数据可出境，无单独同意机制 | 医疗行业客户 | 第 7.4 条 |
| 5 | **对赌条款**：未达 KPI 须回购股权 | 2020 战略投资补充协议 | 补充协议二 |
| 6 | 争议管辖：对方所在地法院 | 标准销售模板 2019 版 | 第 12.2 条 |
| 7 | 自动续约 + 对方单方调价权 | IDC 托管转售合同 | 第 3.8 条 |

陈默脸色发白：「第一条和第五条，任何一条都能让董事会直接否决。」

然而外聘律师老周点开第一条，愣了两秒：「这条连带责任后面有个括号——『以渠道方实际库存账面价值为限，最高不超过人民币 200 万元』。你们系统把标题行标红了，限缩条件在下一行，被 OCR 换行切断了。」

苏晴当场点「误报反馈」，并把该条降级为 P1，同时在工单里备注：**OCR 换行导致条件从属关系丢失**。她在心里记了一笔——合同审查里，一次「狼来了」比漏一条更伤信任。

第五条对赌条款倒是真雷。但更麻烦的是黄灯里藏着的**隐性连锁**：第 6 条「管辖在对方所在地」出现在 2019 版标准模板里，意味着智链过去三年用同一模板签了 47 份客户合同——不是一份合同的问题，是**模板级系统性风险**。

苏晴把视图从「单份合同」切到「模板维度」：「业务方要的不只是七盏红灯，而是『哪几份能签、哪几份要重谈、哪几份该计入估值折扣』。」

**悬念**：天快亮了，律师人手只够深审 15 份——到底先审哪几份？

---

### 第四章：AI 不会替你决定「买不买」，但能告诉你「谈判改没改」

凌晨 3 点，卖方律师回了一版《渠道框架协议》修订稿，陈默问：「能不能再跑一遍，看无限连带责任删干净没有？」

苏晴启动**版本对比审查（Contract Diff）**。系统不是简单 diff 文字，而是：

- 按条款 ID 对齐新旧版本；
- 重新计算风险分：标题里的「连带责任」删了，但附件五新增「双方对渠道库存承担共同回购义务」——语义等价，风险分只从 P0 降到 P1；
- 在侧栏提示：「正文删除项与附件新增项语义相似度 0.89，建议人工复核是否换汤不换药。」

老周差点漏看附件五。他感慨：「人读 68 页容易疲劳，机器擅长『同一主题跨附件追踪』——但『换汤不换药』这种判断，仍然要律师点头。」

与此同时，**审查优先级队列**在自动重排：

- P0 且金额 > 1000 万 → 进「律师深审池」，2 小时内必须有人认领；
- P0 但已过期/已终止 → 降优先级，标注「历史负债风险」；
- 模板级风险 → 生成「模板修复任务」，推给吴婷统一改标准合同；
- 模型置信度 < 0.65 的标注 → 强制进「人工复核队列」，不允许业务方直接导出「无红线」摘要。

吴婷问：「那我们今晚到底省了什么？」

苏晴调出一张对比表：

| 环节 | 纯人工（按以往速度估） | 人机协作（今晚） |
|------|------------------------|------------------|
| 126 份初筛 | 约 9.5 人日 | 3.2 小时机审 + 1 人日律师深审 |
| P0 定位 | 依赖律师经验扫标题 | 7 分钟内全量扫描 + 优先级排序 |
| 模板级风险 | 往往事后纠纷才发现 | 一次性拉出 47 份同源管辖问题 |
| 谈判版比对 | 律师逐字肉眼 diff | 条款级对齐 + 隐性挪条款提示 |

陈默松了半口气：「所以 AI 不是替我们决定买不买，是帮我们在周五中午前**把该谈的雷谈完**。」

**悬念**：董事会要的从来不是「红灯清单」，而是一张能讲清楚「为什么报价还要降 800 万」的风险接受说明。

### 第五章：绿灯不等于能签，交易委员会要的是「谁背锅」

周四 16:00，苏晴导出《智链法律尽调合同风险摘要 v4》：12 页执行摘要 + 118 份合同索引 + 5 项未关闭 P0/P1 及**风险接受理由** + 3 项「建议估值调整项」。

其中两项经谈判关闭：渠道连带责任免责改写并设 200 万上限写入正文；对赌条款改为「业绩补偿金」且设总 caps（上限）。三项以「有条件接受」进入交易委员会：

1. 47 份旧模板管辖条款——计划收购后 12 个月内批量重签或发补充协议；
2. 4 份医疗客户数据出境承诺——需单独合规整改预算 80 万；
3. 2019 版「单方调价权」托管转售合同 2 份——计入 2027 年续签谈判清单。

系统在报告末尾自动生成了**审计轨迹**：谁上传、哪版模型、哪条规则命中、谁点了误报、谁批准风险接受、谁修改了估值模型输入——这对拟上市公司和基金 LP 汇报不是锦上添花，是刚需。

周四 20:00，交易委员会问：「AI 审的，出了问题算谁的？」

苏晴答：「算流程。AI 负责**高召回地找出可疑条款**，律师负责**定性**，投资团队负责**议价和估值调整**，系统记录**谁批准了例外**。没有『模型说能买』这个按钮。」

老周补充：「今晚如果没有批次标注，我们大概率会在 47 份旧模板上栽跟头——不是某一份合同忘了看，是**系统性风险被单份阅读模式藏住了**。」

周五 11:30，报价函签署。陈默在群里发了一句：「尽调最贵的不是律师费，是漏看一条条款后的重新谈判。」

苏晴在复盘文档里写下定义：**合同智能审查与风险标注系统 = 文档解析与批次编排 + 条款切分 + 结构化抽取 + 规则/模型风险识别 + 模板偏离与合同族分析 + 人机协同复核台 + 版本 diff + 风险接受审批 + 条款知识库回写**。不是「AI 律师」，是「法务、投资、业务在高压截止日下的共同工作台」。

# 3. 系统正解

合同智能审查系统的核心数据流是：**合同批次接入与类型路由 → OCR/解析与条款切分 → 关键条款结构化抽取 → 规则引擎 + 风险模型并行标注 → 与公司红线库/标准模板比对 → 合同族与模板级风险聚合 → 风险分级与审查队列分流 → 法务/业务复核台 → 谈判版本 diff 再审查 → 风险接受审批与尽调报告 → 条款知识库回写**。

回扣故事中的关键情节：

- **126 份命名混乱的 PDF** → 文档接入、版本去重、优先级排队；
- **连带责任标红却有限缩条件** → OCR 换行 + 条款从属关系解析失败，触发误报反馈；
- **47 份同源管辖问题** → 模板维度聚合，单份阅读模式覆盖不了的系统性风险；
- **附件五换汤不换药** → 版本 diff + 跨附件语义相似度检测；
- **交易委员会问「算谁的」** → 审计轨迹与风险接受审批链，明确 AI 无签字权。

**AI 产品岗典型应用场景：**

| 场景 | 具体例子 |
|------|----------|
| 需求文档 | 写清「支持批量上传、合同族去重、条款级标注、模板级风险视图、风险接受需双人审批」；明确**不做**自动法律结论、自动签署、自动估值调整 |
| 方案评审 | 业务方说「召回率 98% 就够了」时，同步追问误报率和律师复核工时——尽调场景下，律师把系统当「不可信筛子」比漏一条更致命 |
| 指标设计 | 核心指标：高风险条款召回率、误报率、单份审查节省时长、**模板级风险发现数**、谈判轮次减少数；北极星是「可关闭风险项」而非「标注条数」 |
| 跨团队沟通 | 对法务说「模型帮你找疑点，不替你做定性」；对投资说「红灯是谈判和估值输入，不是否决按钮」；对工程说「条款 ID 对齐比全文 diff 重要，OCR 换行要单独测」 |

# 4. 类比锚定

**类比：机场安检通道（随身行李 X 光机 + 开箱台）**

旅客进站都要过安检：行李进 X 光机，可疑物品贴条分流到开箱台，安检员最终决定能不能带上飞机。合同审查 AI 不是「自动判定你能不能飞」，而是「先把可疑物标出来，让人工快速决策」。

| 机场安检（旧经验） | 合同智能审查（新系统） |
|-------------------|------------------------|
| 旅客身份证件与航班信息 | 合同元数据：类型、金额、期限、双方主体 |
| 行李传送带与批次过机 | 批量上传、解析队列、P0 快车道 |
| X 光成像 | OCR + 条款切分 + 关键字段抽取 |
| 违禁品图像识别规则库 | 公司红线库 + 合同类型 Playbook |
| 可疑物品贴黄条/红条 | 风险分级标注（P0/P1/P2） |
| 开箱复检台 | 法务深审池、低置信度人工复核队列 |
| 液体单瓶容量限制（硬规则） | 数字类条款规则校验（违约金比例、赔偿上限） |
| 安检日志与录像追溯 | 审计轨迹：谁标注、谁误报反馈、谁批准例外 |
| 不同航线安检标准不同 | 销售 / 采购 / 劳动 / NDA 路由不同审查模板 |

# 5. 类比边界与系统要点

## 类比在哪里会失效

安检标准全国相对统一，违禁品定义清晰；合同风险高度依赖交易立场、行业惯例和双方博弈——**「可疑」不等于「违规」**，同一条款在卖方尽调和买方收购里优先级可能完全相反。安检也不会一晚上改十版行李，合同谈判版却在几小时内反复修订。

## A. 系统核心要点总结

- **数据输入要求与格式规范**：需支持可编辑 PDF、扫描件、Word、批量压缩包；要识别合同类型并路由 Playbook；混排附件、多版本命名、合同族去重是尽调场景的常态脏数据；元数据（金额、期限、是否有效）影响优先级和风险权重。
- **AI 模型的能力边界与置信度**：模型擅长语义归纳和跨附件追踪，但不承担法律责任；对数字（违约金、期限）、连带责任是否有限缩等，需规则 + 版面分析校验；低置信标注必须默认升高人工复核优先级，不能进「无红线」摘要。
- **人工介入的触发条件与流程**：新合同类型、首份供应商、P0 红线命中、模型低置信、业务申请风险接受、交易金额超阈值——应走不同审批链；实习生可改标注，不能点「风险接受」或导出尽调结论。
- **系统的容错与降级机制**：解析失败退回「纯人工 + 基础 OCR」，不输出假绿灯；主模型不可用时规则引擎仍可跑硬性红线；版本 diff 失败时保留全文对比兜底；批次中部分文件失败不应阻塞整批可审文件。
- **成本结构**：计算成本随页数 × 批次数线性涨，尽调高峰一月 API 账单可能是平时的 8–12 倍；律师深审时间是隐藏大头；**误报导致的信任崩塌**和**漏报导致的估值失误**远超 API 费用；红线库和 Playbook 需要法务持续运营。

## B. 类比失效点

1. **安检违禁品定义相对稳定，合同「红线」随并购立场变化。** 卖方尽调要暴露风险，买方要量化议价筹码——同一标注在不同角色工作台里应有不同「下一步动作」，不能只有一张报表。
2. **安检漏检可补救，关键条款漏审可能锁死三年。** 产品上要偏向**高召回**，再用律师队列消化误报；不能只追「标注少、界面干净」。
3. **合同谈判版一晚上能改十轮，X 光不会。** 版本对齐、隐性挪条款（正文删、附件加）、换汤不换药检测是尽调高频刚需，安检类比覆盖不了动态博弈。
4. **AI 输出是概率性的。** 同一条款两次标注可能因模型版本、上下文切分不同而波动——关键数字和法律责任类条款要用规则锚定，并保留完整审计日志。
5. **安检员不承担交易后果，企业里「谁批的风险接受」要可追溯。** 基金 LP、董事会、上市审计都会问——类比掩盖了组织设计与合规签名，这些是 PM 必须画进流程图的。

# 6. 深度业务洞察

1. **业务侧：表面要「自动审合同」，真实要「尽调截止日前能报价」**  
   投资总监最怕的不是看不懂法言法语，而是周五中午前答不出「这 800 万估值要不要降」。真实需求是**可执行的谈判清单 + 模板级风险地图 + 版本前后对比 + 风险接受话术**。若报告只有「高风险」标签没有「建议改法、行业惯例、估值敏感性」，律师省下的时间会被交易团队骂回来。

2. **技术侧：条款切分质量决定天花板，大模型救不了烂 PDF**  
   很多项目把预算全砸在「最强 LLM」，却忽视 OCR 换行、条款从属关系、表格跨页。连带责任标题和限缩条件被拆成两行，后面所有风险都标错位——业务一次误报就会永久绕开系统。**工程化难点在文档理解流水线，不在 prompt 写得花。**

3. **运营侧：尽调场景是「批次战」，不是「单份战」**  
   冷启动靠标准模板 diff 和红线库；飞轮转靠「最终签署条款 + 是否引发纠纷 + 估值调整结果」回写。要设计合同族、模板维度、有效期三维视图——否则 AI 永远停在「会标红」，学不会「这条黄灯在智链其实常接受」。

4. **合规侧：审计轨迹与权限隔离不是可选功能**  
   尽调数据室有严格权限：买方律师、卖方法务、投资方不能看同一份标注批注。系统必须从 Day 1 设计**字段级权限 + 不可篡改日志**：谁看了哪份、谁批准了例外、谁导出过报告。缺这个，外聘律所宁可不用 AI，因为工具会变成泄密和合规负债。

5. **商业侧：按份计费 vs 按项目计费，ROI 算法完全不同**  
   卖 SaaS 按「每份合同 X 元」容易，但尽调客户买的是「截止日前出结论」。PM 定价前要算清：批次并发、律师复核工时、误报导致的信任损失、漏报导致的重新谈判——**尽调高峰一个月的收入，可能抵不上一单漏审的估值事故**。

### 动手小练习（30 分钟内）

**练习：给一份 5 页《保密协议（NDA）》设计「尽调批次最小 Playbook」**

1. 找一份公开 NDA 模板（或公司内部模板脱敏版）；  
2. 列出 10 条检查项，分成「规则可判」（保密期限、管辖地、违约金数字）和「需人判断」（保密信息定义是否过宽、是否含竞业限制）；  
3. 标出每条误报/漏报在并购场景下的业务后果（估值调整 / 交易终止 / 合规整改）；  
4. 写一句「必须进律师深审池」的触发条件，和一句「可批量绿灯」的触发条件。

**目标**：体验 PM 在合同 AI 里最有价值的交付物不是 prompt，而是**可运营的 Playbook、优先级队列与风险接受策略**。
