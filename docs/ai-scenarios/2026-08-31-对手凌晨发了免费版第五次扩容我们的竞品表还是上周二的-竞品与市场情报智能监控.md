# 2. 业务场景故事

## 《对手凌晨发了免费版第五次扩容，我们的竞品表还是上周二的》

### 第一章：周一晨会前二十分钟，CEO 问了一个所有竞品表都答不了的问题

9 月 1 日周一 08:40，企业级营销自动化 SaaS「脉流」的产品晨会还没开始。CEO 陈总把手机推到会议桌上，屏幕上是竞品「烽火 CRM」昨晚 23:17 发的官方博客：

> **「免费版永久开放 API 调用，每月 10 万次，含 webhook 与基础自动化。」**

脉流的核心卖点之一是「开放生态 + 自动化编排」。免费版此前 API 每月仅 500 次，销售团队一直用这张对比表打中型客户——**这张表是上周二竞品分析师小赵手工更新的**。

陈总看向刚接手 AI 产品方向的林涛：「三件事：他们这次动了什么、对我们哪条客户群威胁最大、今天下班前销售能不能拿到新话术。别告诉我你们还在等小赵刷完微博。」

林涛打开内部 Notion「竞品动态库」，最新一条记录停在 8 月 26 日：「烽火发布秋季 UI 改版」。API 扩容、价格页变更、应用商店描述修改——**全不在库里**。

销售 VP 在群里已经炸了：「昨晚就有客户在问『烽火免费就能接 API 了，你们专业版凭什么贵三倍？』」

小赵辩解：「我周末没值班，官网变更没有邮件通知，博客 RSS 我周一早上才扫……」

林涛意识到：问题不是小赵不努力，而是**情报获取靠人记忆 + 固定节奏**，而竞品动作是 7×24 小时、多渠道、碎片化发生的。他们需要的不是一份更长的 Excel，而是一套 **「持续监听 → 自动结构化 → 分级告警 → 人工研判」** 的流水线。

**悬念**：林涛以为「竞品监控 = 爬虫 + 大模型总结」，很快他会发现，真正决定情报价值的，是 **信源权重、变更 diff、业务规则阈值、以及谁有权把一条推送升级成「今日必回应」**。

### 第二章：一条市场信号进来，后台要跑五层流水线

林涛拉着竞品分析师小赵、数据工程老周和 NLP 负责人苏曼，把晨会事故复盘成标准链路。以「烽火 API 免费扩容」为例，系统从发现到进入销售话术库，实际经过五层：

**第一层：多源采集（工程为主，规则调度）**

情报源不是只有官网，而是分层覆盖：

| 信源类型 | 采集方式 | 典型延迟 | 本案例命中情况 |
|---------|----------|----------|----------------|
| 竞品官网 / 定价页 | 定时快照 + DOM diff | 15 分钟–1 小时 | 定价页「API 额度」文案 23:05 变更 |
| 官方博客 / Changelog | RSS + 全文抓取 | 30 分钟 | 23:17 博文发布 |
| 应用商店 | 版本描述 API 轮询 | 2–6 小时 | 未改描述，**单靠商店会漏** |
| 社交媒体 / 技术社区 | 关键词监听（品牌词 + 高管账号） | 实时–30 分钟 | 00:42 有 KOL 转发，互动量上升 |
| 招聘网站 / 专利 / 监管公示 | 日级批处理 | 1–3 天 | 本周不相关 |
| 客户与渠道反馈 | CRM「竞品提及」字段汇入 | 不定 | 周一早 8 点已有 3 条工单提及 |

老周强调：**采集层不做「理解」，只做「有证据的变更记录」**——每次快照存 HTML hash、截图、时间戳，日后销售被客户质疑时能调出「我们何时看到什么」。

**第二层：事件检测与去重（规则 + 轻量模型）**

同一新闻可能被博客、微博、科技媒体转载五次。系统先做 **事件归并（Event Clustering）**：

- 标题相似度 + 链接跳转关系 + 时间窗（24 小时内同源）→ 合并为事件 `EVT-20250901-烽火API免费扩容`；
- 去重后保留 **最早信源** 与 **最高权威信源**（官网 > 自媒体转载 > 论坛猜测）。

论坛有人发帖「听说烽火要收购脉流」——无官网佐证，标记为 **「未证实传闻」**，不进入销售告警，只进分析师低优队列。

**第三层：语义结构化抽取（AI 核心）**

大模型（或专用信息抽取模型）把非结构化文本转成 **竞品动作卡片**：

```json
{
  "competitor": "烽火 CRM",
  "action_type": "product_capability_change",
  "subtype": "api_quota_increase",
  "summary": "免费版 API 调用额度由 500次/月 提升至 10万次/月，含 webhook 与基础自动化",
  "pricing_impact": "免费版对中型客户的集成门槛显著降低",
  "target_segment": ["SMB", "开发者", "轻量自动化场景"],
  "confidence": 0.92,
  "evidence_urls": ["https://...", "定价页 diff 截图 ID"],
  "effective_date": "2026-09-01"
}
```

AI 在这里的角色是 **「翻译官」**：把博客公关话术翻译成产品语言（能力变更、影响客群、与我方差异）。**不是「分析师」**：是否构成战略威胁，不能由模型拍板。

抽取层还要跑 **对比基线（Baseline Diff）**：自动拉出脉流免费版/专业版对应能力表，生成「差异变化矩阵」——本次高亮：API 额度、webhook、自动化节点数。

**第四层：影响评分与告警分级（规则 + 模型混合）**

苏曼的模型输出 `threat_score` 建议值 0.78（高），但最终分级由规则引擎裁决，输入包括：

- **动作类型权重**：定价变更、核心能力免费开放 > UI 改版 > 品牌联名；
- **客群重叠度**：与脉流本季度主攻的「50–200 人电商团队」重叠 0.85；
- **销售管道冲击**：CRM 里 23 个活跃商机近 7 天提及「烽火」；
- **情绪与声量**：社交媒体声量 6 小时内 +340%，情绪中性偏正面（对烽火）；
- **可响应性**：脉流是否有对标能力或话术，响应 SLA 是否来得及。

本事件被定为 **L2 告警（当日必须回应）**：推送给产品、销售、市场三方负责人，附带 AI 草稿「威胁解读」与「差异表 diff」。

**第五层：人工研判与行动分发（人拍板）**

小赵 9:15 进入「情报校验台」，30 分钟内完成：

1. **确认事实**：核对官网 diff，排除「博客写错、实际未生效」——本次已生效；
2. **修正 AI 表述**：模型把「基础自动化」夸大成「全功能自动化」，小赵改为「仅含 3 个预设模板」；
3. **标注战略判断**：「威胁中型客户，对大企业 API 治理需求影响低」；
4. **触发行动包**：一键分发——销售话术库更新、Battlecard 红条标注、客户成功关注列表 23 个商机标星。

林涛 17:00 前拿到陈总要的第三件事：**不是小赵写的八页 PPT，而是带证据链的一页纸 + 销售可直接复制的三段话**。

**关键设计点**：AI 负责「发现变更、结构化、初评」，竞品分析师负责「证实、纠偏、定调」，销售负责「落地话术」——**情报系统的终点是行动，不是档案**。

### 第三章：哪些环节必须留人，哪些可以全自动

灰度上线两周后，林薇（产品总监）问了三个尖锐问题，直接决定人机边界：

**「能不能所有竞品动态都自动推销售群？」——不能。**

全自动推送的后果：

- **噪音淹没**：竞品修了个错别字、换个 Banner，diff 也会触发告警，销售群一天 40 条「狼来了」；
- **误报伤人**：媒体误读「烽火降价 30%」，实际只是限时优惠券，自动推送会导致销售乱承诺；
- **战略泄露**：未证实并购传闻若自动进大群，内部恐慌先爆发。

系统设计三档边界：

| 档位 | 触发条件 | 系统行为 | 人的动作 |
|------|----------|----------|----------|
| 自动归档 | 低影响变更（UI 微调、博客无关痛痒） | 写入情报库，周报汇总 | 无 |
| 分析师校验 | 新事件、threat 0.4–0.8、或跨多产品线 | 推送校验队列 | 30–60 分钟内确认/降级/合并 |
| 高管告警 | 定价、核心能力免费、大客户流失实锤、监管政策 | 即时推送 L1/L2 | 产品+销售 2 小时内碰头 |

**「官网和社交媒体谁说了算？」——官网为准，社媒为早预警。**

社媒可能提前 6 小时泄密，但也可能是谣言。规则：**社媒单独命中 → 黄色预警；官网 diff 确认 → 升级为红色**。销售对外话术必须绑定「已证实证据链」，不能只有截图。

**「AI 写的威胁解读销售能直接用吗？」——只能当草稿。**

大模型爱写「颠覆性」「毁灭性打击」——销售对客户过度防御反而丢单。模板强制要求：**事实一句、影响一句、我方差异一句、禁止词汇表（「颠覆」「必死」）**。

**「竞品动作要不要自动同步到产品 backlog？」——要建议，不能自动建需求。**

「烽火开放 API」不等于「脉流也要免费无限 API」——可能是定价策略调整、可能是生态卡位。系统输出 **「响应选项 A/B/C + 预估成本」**，PM 在评审会上选，不自动创建 Jira。

### 第四章：AI 搞不定的时候，系统怎么优雅降级

灰度第四周，系统踩了四个坑，也验证了降级是否生效。

**坑 1：竞品反爬升级，定价页快照连续失败 36 小时**

烽火把定价页改成前端动态渲染 + 地域差异化展示，静态爬虫抓到的是空壳。

**降级动作**：

- 监测到「核心信源连续失败 &gt;3 次」→ 自动切换 **无头浏览器快照队列**（成本更高，仅核心竞品启用）；
- 告警降级为「采集健康度红灯」，Dashboard 明示「定价页数据可能滞后」；
- 临时启用 **人工补录入口**：小赵上传截图也可触发结构化流程，不绕过校验闸门。

**坑 2：大模型把「合作伙伴接入 API 市场」总结成「免费开放全部 API」**

博客原文是「开发者市场第三方插件可调用」，模型幻觉成官方核心 API 全免费。

**降级动作**：

- 结构化结果必须 **逐条绑定原文 span（原文高亮片段）**，无 span 的字段标红「待证实」；
- 涉及「定价 / 免费 / 额度」类字段，**强制双人校验** 才能进 L2 告警；
- 错误摘要进入 hard negative 样本库，周度复盘。

**坑 3：声量暴涨但其实是公关水军刷榜**

某竞品雇水军在微博刷「行业第一」，互动量异常但信源单一、评论模板化。

**降级动作**：

- **声量异常检测**：同文案重复率、账号集中度、信源多样性不足 → 标记「疑似操纵」；
- 不升级告警，仅进分析师「舆情观察」；
- 避免脉流被动跟风发声明——**有时候最好的回应是不回应**。

**坑 4：周一情报洪峰，结构化队列排队 4 小时**

三家竞品同周办发布会，博客、直播字幕、媒体稿同时涌入。

**降级动作**：

- **竞品优先级队列**：直接竞争对手 &gt; 间接竞品 &gt; 生态伙伴变动；
- **流式处理**：博客标题 + 首段先出「快报」，全文结构化完成后补全 diff；
- **熔断展示**：延迟 &gt;2 小时时，晨会材料自动附加「截至 08:00 情报，后续更新见链接」。

林涛在复盘里写了一句：**「情报系统最大的失败不是漏报，而是用错误情报帮对手吓跑了自己的客户。」**

### 第五章：成本与效率——为什么不继续让人刷官网

陈总问：「小赵一个人盯五家竞品，加个系统值吗？」

林涛算了一笔账：

| 项目 | 纯人工（1 分析师 + 销售各自打听） | AI 情报流水线 + 人工校验 |
|------|-----------------------------------|---------------------------|
| 核心竞品日报覆盖 | 滞后 1–3 天，漏周末夜间 | 关键变更 &lt;1 小时发现 |
| 单次重大事件响应 | 4–8 小时拼凑材料 | 校验后 1–2 小时出行动包 |
| 误报导致销售踩坑 | 难追溯，靠口头纠偏 | 证据链 + 双人校验降低 |
| 直接成本 | 分析师人力 ¥25k/月 | 采集+推理+存储约 ¥3–8k/月 + 分析师时间减半 |
| 隐性成本 | 丢单、被动降价、话术不一致 | 错误 L2 告警引发内部混乱（需严控） |

销售 VP 补了一句更实在的：**「上周有个单子，客户拿竞品上周五的公告压价 15%，我们周一才知道——这不是分析师工资的问题，是时机问题。」**

林涛反应过来：**这套系统的价值不是「替代竞品分析」，而是把分析师从「刷网页」里解放出来，去做「判断威胁、设计回应」**——而判断，必须建立在可审计的证据链上，不是微信群转述。

# 3. 系统正解

**竞品与市场情报智能监控系统**，是一条从多源信源采集与快照存证 → 变更检测与事件归并 → AI 语义结构化与基线 diff → 威胁评分与分级告警 → 人工校验与战略标注 → 行动包分发（话术 / Battlecard / 商机标记）的流水线。故事中，烽火 23:17 的博客对应 **官方信源采集**；定价页先于博文变更对应 **DOM diff 早预警**；小赵修正「基础自动化」范围对应 **人工校验纠偏**；23 个商机标星对应 **CRM 交叉命中**；爬虫失败 36 小时对应 **采集健康监测与人工补录降级**。

| 场景 | 具体例子 |
|------|----------|
| 需求文档 | 写清「信源列表与采集频率、diff 灵敏度、L1/L2/L3 告警定义、双人校验字段、行动包模板、采集失败时的展示策略」；明确 AI 输出是「结构化草稿」不是「战略结论」 |
| 方案评审 | 业务方说「竞品一有动静就推全员」时，追问「误报谁负责、销售群告警上限、未证实传闻如何隔离」——无校验的情报推送等于自动造谣 |
| 指标设计 | 核心：重大变更发现 lead time（竞品生效→我方确认）、误报率（降级/撤回告警占比）、漏报率（事后复盘才发现）、采集成功率、校验 SLA 达标率；北极星是「可响应威胁的发现时长」，不是「抓取条数」 |
| 跨团队沟通 | 对销售说「带证据链和差异表，不是转述公众号标题」；对法务说「未证实情报对外禁用」；对工程说「核心页面采集失败是 P0 运维事件」；对数据说「信源变更要版本化，方便复盘『当时我们看到了什么』」 |

# 4. 类比锚定

**类比：财经媒体的「快讯台 + 编辑复核」——记者抢首发，编辑把关才能上头条推送**

彭博、路透、财联社的工作方式：记者和算法监控全球信源，先出「快讯」；编辑核实来源、补充上下文，再决定推「红色推送」还是放进日报。**AI 采集与结构化 = 快讯机器人；竞品分析师 = 编辑；L2 告警 = 上推送；L1 = 打电话叫醒值班主编。**

| 财经快讯台（旧经验） | 竞品情报智能监控（新系统） |
|---------------------|---------------------------|
| 记者驻点、电报、公告 API | 官网快照、RSS、商店、社媒监听 |
| 快讯「据XX报道」 | 结构化卡片 + 证据 URL / diff 截图 |
| 编辑核实信源等级 | 分析师校验、双人复核定价类 |
| 谣言辟谣、暂不推送 | 未证实传闻隔离、疑似水军降权 |
| 红色推送 vs 日报汇总 | L1/L2 即时告警 vs 周报归档 |
| 快讯 + 深度稿 | 事实卡片 + 威胁解读 + Battlecard |
| 行情终端分发给交易员 | 行动包分发给销售、PM、市场 |
| 错误快讯撤回与问责 | 告警撤回记录、误报复盘样本 |

# 5. 类比边界与系统要点

## 类比在哪里会失效

财经快讯有交易所、证监会等 **权威单一信源**；竞品情报是碎片化、公关化的，同一动作可能六个渠道六种表述。**财经有毫秒级共识需求，竞品情报有战略模糊性**——「开放 API」到底是技术普惠还是获客陷阱，快讯台逻辑回答不了。媒体快讯对外，竞品情报 **高度内部敏感**，权限与泄露风险远超编辑部。

## A. 系统核心要点总结

- **数据输入要求与格式规范**：信源需登记（URL、采集方式、频率、合法合规边界）；快照与 diff 必须存证（时间、 hash、截图）；结构化输出需统一 schema（动作类型、影响客群、证据链、置信度）；与内部 CRM、定价表、能力矩阵 **版本对齐**，否则 diff 无基线。
- **AI 模型的能力边界与置信度**：擅长摘要与字段抽取，不擅长战略判断与「对手真实意图」；对定价、免费、额度类字段幻觉代价极高；社媒情绪与声量易被操纵——必须展示置信度、原文 span、信源等级，低证实度禁止进销售通道。
- **人工介入的触发条件与流程**：定价/能力变更、并购传闻、大客户流失、监管政策 → 分析师校验；涉及对外话术 → 销售+市场会签；双人校验适用于高影响字段；校验 SLA 建议 L2 &lt;2 小时，否则情报价值衰减为「事后档案」。
- **系统的容错与降级机制**：采集失败时健康度红灯 + 人工补录；结构化延迟时流式快报；高负载时竞品优先级队列；模型不可用时退回规则模板 + 纯人工卡片；Dashboard 标注数据截止时间；支持告警撤回与审计追溯。
- **成本结构**：常驻采集与快照存储；无头浏览器与代理池成本；大模型结构化按事件计费；分析师校验时间（显著低于纯人工刷网页）；**误报 L2 导致销售乱承诺、被动降价** 的隐性成本远高于算力；持续维护信源与纠偏样本的运营人力。

## B. 类比失效点

1. **快讯错了可以撤回，销售对客户说错话很难撤回。** 情报系统对外的唯一出口往往是销售话术——误报一次，客户会记住「你们上周还说对手没这功能」，比媒体撤稿伤害更持久。
2. **财经信源有法律效力边界，竞品情报常踩爬虫与数据合规灰区。** 类比掩盖了 robots 协议、地域隐私法、平台 ToS——产品要定义 **合法采集白名单**，不能默认「能爬到就是能用」。
3. **市场涨跌是概率共识，竞品动作解读是多方博弈。** 同一「免费 API」动作，可能是烧钱获客、可能是功能鸡肋、可能是逼你降价——AI 只能列选项，不能替 CEO 选战略响应。
4. **快讯模型追求全覆盖，竞品监控必须聚焦。** 盯五十家「可能有关系」的公司，分析师和告警都会崩溃——产品要先定义 **Tier 1 直接竞品 + 关键信源**，再谈 AI 全覆盖幻想。
5. **媒体是单向广播，情报系统要和 CRM、商机、定价、路线图双向联动。** 只会推微信群、连不上「哪些客户在比价」的玩具，销售三天就静音群消息——**交叉命中** 才是让销售愿意看告警的关键。

# 6. 深度业务洞察

1. **业务侧：老板要「竞品动态」，其实要「我明天怎么卖、要不要改 roadmap」**  
   表面需求是「竞品周报」；真实需求是 **可执行的差异叙事**——哪类客户会动摇、我方哪条能力仍是护城河、短期话术 vs 中期产品怎么分工。只给「对手发了博客」链接合集，晨会照样吵一小时。交付物应是 **带证据的行动包**，不是情报档案柜。

2. **技术侧：diff 比摘要更重要，基线比模型更重要**  
   很多团队先买「大模型竞品分析」，却连自家能力表、竞品定价页 **结构化基线** 都没建好——AI 只能写泛泛威胁感。工程上 **快照 diff + 字段级变更** 往往比换更强的摘要模型更能减少误报；模型负责填表，规则负责_alarm。

3. **运营侧：冷启动靠人工种子，成熟期靠「误报复盘飞轮」**  
   新竞品上线前，分析师先手工录入能力矩阵与信源清单；每次「告警撤回、字段纠错」都应进入抽取样本。若校验结果不回灌，三个月后系统仍靠小赵肉眼补洞。竞品分析师时间从「刷网页」转向「校验 + 标注」，编制不能省，只是换工种。

4. **合规侧：采集合法、情报分级、对外口径可审计**  
   爬虫需法律评估；员工社媒、客户聊天记录作信源需授权；未证实并购传闻在内部也要权限控制。对外销售话术需记录「基于哪条已证实情报」——监管或合同纠纷时，**情报系统即证据系统**。

5. **商业侧：ROI 算「少丢一个因信息滞后丢的单」，不算「少雇一个实习生」**  
   一次中型客户因竞品动作压价 15%，损失远超系统年费。对内立项用「管道冲击商机数 × 平均客单价 × 滞后天数」比「节省 20 人时」更能打动管理层。对外若做 SaaS 情报产品，按 **监控竞品数 + 信源深度 + 告警席位** 分档，勿按「抓取条数」计费——条数越多噪音越大。

### 动手小练习（30 分钟内）

**练习：手工模拟一次「竞品变更卡片」**

1. 选一个你熟悉领域的直接竞品，打开定价页和 Changelog，截图保存「今天」的状态；  
2. 找一份一周前的同类页面（可用 Wayback Machine 或自己上周截图）；  
3. 人工列出 **3 条以内** 的「事实级变更」（只写能指着截图说的话）；  
4. 用任意 AI 工具根据 Changelog 生成「威胁解读」，标出 1 处夸大或幻觉；  
5. 写一句：若你是销售，哪些字段必须经过人工校验才能对客户说？

**目标**：体验 **「diff 是证据，摘要只是草稿」**——以及为什么情报系统的护城河是 **基线数据 + 校验闸门**，不是更会写的模型。
