# 2. 业务场景故事

## 《换模型后的第七天，Dashboard 全是绿的，差评却涨了四成》

### 第一章：周五晚上全量，周一晨会一片祥和

9 月 5 日周五 21:40，跨境客服 SaaS「语桥」的在线机器人完成了一次「例行升级」：把意图识别和回复生成从旧版 7B 小模型，换成厂商新发布的 14B 对话模型。算法负责同学老何发了一条群消息：「离线评测准确率 89.2% → 92.6%，延迟 P95 从 1.8s 降到 1.2s，建议直接全量。」

刚转行做 AI 产品的林溪看着评测报告点头——数字漂亮，老板也催「大促前把机器人再提一档」。她 PRD 里只写了三句验收标准：准确率提升、延迟不劣化、无 P0 事故。22:15，运维点了全量发布。

周一晨会，林溪汇报：「周末机器人平稳，错误率 0.3%，平均响应 1.1 秒，全绿。」客服总监苏蔓没抬头：「用户没骂就行。」

**悬念**：林溪不知道，Dashboard 上的「错误率」统计的是 **接口超时和 5xx**，不是 **用户觉得机器人答错了**。

---

### 第二章：第七天，差评区先炸了

9 月 12 日周四 10:20，应用商店和工单系统同时抬头。

运营同学截了一张图进群：德语站 **「机器人听不懂人话」** 类差评，七天环比 **+42%**；其中 **退款意图** 相关会话里，用户重复提问次数（同一用户 10 分钟内问 ≥3 次）从 8% 升到 19%。

更刺眼的是一条 VIP 工单原文（用户用德语写，客服译成中文）：

> 「我第三次说我要退整单，它还在给我发 10% 优惠券。我要真人。」

苏蔓 @ 林溪：「你周五说的全绿，绿的是什么？」

林溪打开监控大盘——**依然全绿**：API 成功率 99.7%，P95 延迟 1.15s，模型服务 CPU 正常。她第一反应是：「是不是德语站运营活动带来的流量结构变化？」

老何甩出离线对比表：「新模型在测试集上退款意图 F1 更高啊。」

**第二个产品二选一**来了：先 **连夜回滚旧模型** 止血，还是 **再观察两天** 等数据稳？

苏蔓要回滚。林溪犹豫：「回滚要重新走发布流程，大促预热不能停服。」最终折中：**先对德语站 + 退款意图会话切 30% 流量回旧模型（灰度回滚）**，其余继续观察。

**悬念**：为什么离线涨了、在线却翻车？林溪发现，评测集里 **没有「用户边骂边要退、中间夹杂优惠券咨询」的混合意图对话**。

---

### 第三章：影子流量里，真相在「没上线的 5%」

周四下午，林溪拉着数据分析师和工程复盘。他们翻出发布当晚其实开着的 **影子模式（Shadow Mode）**：新模型在后台对 5% 流量「偷偷跑答案」，但不发给用户，只记日志对比。

影子对比表让会议室安静了两秒：

| 维度 | 旧模型（用户实际看到） | 新模型（影子跑、未展示） |
|------|------------------------|--------------------------|
| 整体「用户重复提问率」 | 9.1% | 11.4% |
| 退款类会话重复提问率 | 8.0% | **22.7%** |
| 「答非所问」人工标注占比（抽样 200 通） | 6.5% | **14.8%** |
| 平均响应延迟 | 1.7s | 1.2s |

新模型 **更快、测试集更准**，但在 **高情绪 + 复合意图** 片段里，更容易「自信地答错」——用户要退整单，模型抓到了「优惠」关键词，走了营销话术分支。

林溪意识到：周五全量前，影子流量只有 5%，且 **没被纳入发布门禁（Release Gate）**；门禁只看接口错误率和离线 F1。

**AI 介入时机**在这里很清楚：

- **发布前**：影子对比 + 分桶离线评测（按意图、语言、用户等级切片）→ 决定是否扩大灰度
- **发布中**：按站点/意图/用户等级做 **金丝雀发布（Canary，先放一小撮真实流量试水）**，不是只有「0% 或 100%」
- **发布后**：业务侧指标（重复提问、转人工率、差评标签）与技术指标 **同一屏、同一告警级别**

**人工介入**：当 **任一业务红线** 触发（如 VIP 转人工率 +5pp、退款意图重复提问 +10pp），自动 **缩小新模型流量或回滚**，值班 PM 30 分钟内确认是否人为误报。

---

### 第四章：回滚不是失败，门禁才是产品

周五凌晨 01:10，工程完成「退款意图 + 德语站」100% 回旧模型；其余流量新模型从 100% 降到 **20% 金丝雀**。

林溪连夜改 PRD，补了一张 **发布门禁表**——以后任何「换模型」必须满足：

| 门禁项 | 阈值 | 数据源 | 未达标动作 |
|--------|------|--------|------------|
| 接口成功率 | ≥99.5% | APM | 自动暂停扩量 |
| P95 延迟 | ≤2.0s | APM | 自动暂停扩量 |
| 影子-业务：重复提问率差值 | 新模型不得高于旧模型 +2pp | 影子日志 | **禁止扩量** |
| 金丝雀-业务：转人工率 | 不得高于基线 +3pp（按意图分桶） | 工单系统 | 自动缩金丝雀 |
| 金丝雀-体验：差评标签率 | 7 日滚动不得 +15% | 应用商店+工单 | 值班 PM 告警 |
| 人工抽检 | 每扩量 10% 抽 50 通，答非所问 ≤8% | 标注平台 | 人工否决扩量 |

老何嘟囔：「门槛是不是太多了？」林溪回：「周五全量因为门槛太少。」

第二周，他们在 **混合意图对话** 上补了 120 条标注进训练集，新模型 v2 再走一遍：**5% 影子 → 5% 金丝雀 → 20% → 50% → 100%**，每阶停留至少 48 小时。大促前三天全量完成，德语站差评标签率回到升级前水平。

苏蔓在复盘会上说：「以后我不看『全绿』，我看 **门禁表有没有红灯**。」

---

### 第五章：监控不是仪表盘，是「实验合同」

月底，林溪把这套能力包装成对内产品：**AI 发布控制台**——业务方以后换 Prompt、换模型、换检索库，都走同一条流水线。

她发现 PM 最容易写错的，不是「要不要 A/B」，而是 **实验合同（Experiment Contract）** 五要素有没有写清：

1. **谁是被影响用户**（全量用户 vs 某语言站 vs 某意图桶）  
2. **什么是成功**（业务指标优先，技术指标保底）  
3. **什么是失败**（自动回滚条件，写数字不写「体验变差」）  
4. **观察多久**（大促前禁止 24 小时扩满）  
5. **谁有权拍板回滚**（值班 PM + 客服负责人双签）

故事中段读者应意识到：这不是「运维发布系统」，而是一套 **把 AI 不确定性关进笼子里的产品机制**——和对话机器人、质检打分是同一棵树上的不同果子。

**成本与效率权衡**：影子流量 doubles 算力成本约 5% 流量；金丝雀多阶段拉长上线周期 1–2 周。但对比 **一次错误全量导致的差评、赔付、紧急回滚人时**，林溪在 ROI 表里写：**「一次德语站翻车 ≈ 4 人周 + 品牌伤害」**。

# 3. 系统正解

**AI 灰度发布与效果监控系统**，是一套把「模型/Prompt/检索配置变更」从一次性运维操作，变成 **可观测、可门禁、可回滚的受控实验** 的平台。核心组件：**变更注册中心**（记录版本 diff）、**流量调度层**（影子 / 金丝雀 / 全量）、**双轨指标管道**（技术指标 + 业务体验指标）、**分桶聚合引擎**（按意图/语言/用户等级切片）、**发布门禁与自动动作**（暂停扩量/缩金丝雀/触发回滚）、**人工抽检与标注回流**（扩量前否决权）、**决策与审计日志**（谁、何时、因哪条门禁发布或回滚）。

数据流：变更提案 → 离线评测 → 影子对比 → 金丝雀小流量 → 门禁校验 → 阶梯扩量 → 全量或回滚 → 线上坏例回流训练集。

回扣故事：**周五全量** 对应缺少门禁的一键发布；**Dashboard 全绿** 对应只看 API 指标的技术管道；**差评 +42%** 对应业务指标分桶未监控；**影子日志** 对应影子模式模块；**退款意图灰度回滚** 对应流量调度 + 自动缩金丝雀；**门禁表** 对应发布控制台的产品核心；**v2 五阶段扩量** 对应标准受控实验流水线。

**AI 产品岗典型应用**：

| 场景 | 具体例子 |
|------|----------|
| 需求文档 | 写清实验合同五要素；禁止只写「准确率提升 x%」而无业务指标、无回滚阈值 |
| 方案评审 | 用「换模型全量」案例问研发：影子流量是否默认开启、金丝雀是否支持按意图分桶、回滚是否一键切流量而非重新发版 |
| 指标设计 | 核心指标：分桶转人工率、重复提问率、差评标签率、门禁触发次数、回滚 MTTR；勿用单一离线 F1 代表上线成功 |
| 跨团队沟通 | 给客服总监一张「红灯含义表」：哪个门禁触发会缩流量、是否会自动回滚、值班谁签字 |

# 4. 类比锚定

**核心类比：新药上市与不良反应监测（Phased Drug Launch & Adverse Event Monitoring）**

传统互联网功能上线，像食品换包装——全渠道同一天上架，不好吃明天改配方。AI 模型/Prompt 变更，更像 **新药上市**：临床前（离线评测）过了，还要 **Ⅰ期小样本安全性**（影子）、**Ⅱ期真实患者对照**（金丝雀）、**Ⅲ期扩大样本监测不良反应**（阶梯扩量），任何 **严重不良反应（SAE）** 触发暂停或召回（回滚）。Dashboard 上的「API 成功率」相当于只监测「药片有没有碎」，没监测「病人有没有过敏」。

### 类比映射表

| 旧经验（新药上市） | 新系统（AI 灰度与监控） |
|--------------------|-------------------------|
| 临床前动物/体外试验 | 离线评测集、基准测试（F1、延迟） |
| Ⅰ期健康志愿者小样本 | 影子模式：新方案不算真实暴露，只记对比日志 |
| Ⅱ期对照试验（治疗组 vs 对照组） | 金丝雀：部分真实用户看到新模型，其余仍旧版 |
| 不良反应上报与 SAE 暂停规则 | 业务红线门禁：转人工率、差评、重复提问超阈值自动缩流/回滚 |
| 国家药监局扩批适应症 | 产品/客服负责人双签扩大流量比例 |
| 上市后持续监测与召回 | 全量后滚动监控 + 坏例回流标注 + 紧急回滚 |
| 说明书与禁忌症 | 实验合同：适用用户桶、成功/失败定义、观察期 |

# 5. 类比边界与系统要点

## A. 系统核心要点总结

- **数据输入要求与格式规范**：离线集需 **按意图/语言/情绪分桶**，不能只有一个「总准确率」；线上日志需带 **实验版本 ID、流量桶、用户等级**；差评与工单需能 **映射回模型版本**。  
- **AI 模型的能力边界与置信度**：离线提升不保证在线提升；**复合意图、长尾语言、对抗性用户** 是灰度重点桶；模型「自信答错」比「犹豫答错」更危险，需单独监控。  
- **人工介入的触发条件与流程**：门禁自动动作到「缩流量/暂停扩量」；**全量回滚、对外公告** 需人工双签；每扩量 10% 的人工抽检拥有 **一票否决权**。  
- **系统的容错与降级机制**：新模型失败时 **秒级切流量回旧版**，不依赖重新发版；影子/金丝雀失败时 **默认保持旧版**，新变更不得绕过门禁。  
- **成本结构**：计算成本（影子+金丝雀额外算力、多版本并存）、人工成本（值班 PM、抽检标注）、纠错成本（错误全量的赔付与品牌）—— **阶梯上线的人力成本，通常远低于一次翻车的纠错成本**。

## B. 类比失效点

1. **药品受严格法定监管，AI 发布很多团队靠自觉**。药监局有强制 SAE 上报；你的产品若没有 **门禁硬编码进发布流水线**，工程师深夜仍可能「评测涨了直接全量」——**组织流程与工具必须一起改，类比不能替代发布纪律**。  
2. **药品不良反应有相对稳定的生物学机制，用户行为会随大促、舆情突变**。新药监测期内人群相对固定；你的机器人在大促前 **流量结构剧变**，同一门禁阈值可能误报或漏报——**门禁要支持按时段/活动动态基线**，不能全年一套数。  
3. **药品召回成本极高且罕见，AI 回滚在工程上应很廉价**。若你们回滚还要重新打包发版两小时，产品上的「可回滚」只是口号——**流量切换能力必须前置投资**，这是互联网相对医药的独特优势，别浪费。  
4. **新药不能对同一病人同时试两版，互联网可以影子/金丝雀**。类比在 **影子双跑算力、用户无感对比** 上没有对应物，这是 AI 系统独有的「免费对照试验」能力，**不做影子等于白浪费工程能力**。

# 6. 深度业务洞察

1. **业务侧：客服总监要的是「别在用户发火时火上浇油」，不是「模型分数更高」**  
   表面需求是「升级大模型」；真实需求是 **大促高峰少转人工、少赔付、少差评**。只汇报 F1 和延迟，等于跟总监说「药片更圆了」却没谈过敏率。

2. **技术侧：最难的是分桶聚合与实验归因，不是接个 A/B 框架**  
   同一用户会话跨多轮，版本标签要 **会话级一致**；退款意图要能和 **工单、差评、重复提问** 打通。很多团队只有模型 APM，没有 **业务指标归因管道**——门禁永远缺一半。

3. **运营侧：坏例回流是飞轮，但冷启动期抽检不能省**  
   全量后坏例自动进标注队列；但 **每一档扩量前的 50 通抽检** 是花钱买来的保险。省掉抽检，等于新药不加监测直接进省。

4. **合规侧：VIP 与金融类意图回滚往往要留审计日志**  
   谁批准全量、谁批准回滚、当时门禁数值是多少——toB 客户问「你们 9 月 5 日为什么给用户发了错误优惠承诺」时，需要 **实验合同 + 决策日志** 可导出。

5. **商业侧：对内算「少一次翻车」，对外 SaaS 按「受控发布席位」计费**  
   一次错误全量的客服加班与赔付，常超过全年监控平台费用。对外若做产品化，按 **并发实验数 × 分桶维度 × 保留日志天数** 分档；勿按「模型调用次数」单独卖门禁——会与算法成本混淆，客户看不懂价值。

### 动手小练习（30 分钟内）

**练习：为一次「换 Prompt」写实验合同**

1. 假设你的客服机器人要把退款话术从「先安抚再询问」改成「先核验订单再安抚」；  
2. 填写实验合同五要素：影响用户桶（例如仅中文站 10%）、成功指标（退款会话转人工率下降）、失败指标（重复提问率 +3pp 或 VIP 转人工 +2pp 自动缩流）、观察期（72 小时）、回滚签字人（你 + 客服负责人）；  
3. 列 **3 个离线评测测不到的线上风险**（例如用户边骂边发订单截图）；  
4. 写 **影子模式要对比的 2 个指标**（技术指标 1 个 + 业务指标 1 个）；  
5. 用一句话向研发描述「回滚」：**切流量而非重新发版**，并写清期望 MTTR（例如 &lt;5 分钟）。

**目标**：体验 **「AI 发布 = 受控实验，Dashboard 全绿 ≠ 实验成功」**——以及为什么 PRD 里必须同时写 **成功指标、护栏指标、自动动作**。
